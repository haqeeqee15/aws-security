AWS Incident Manager Real-World Example

Responding to a Security Incident with AWS Incident Manager
Situation : A company is hosting a website on AWS, and the security team has set up monitoring using CloudWatch Alarms to identify unusual access patterns. One day, an alarm is triggered, indicating a potential security breach.

Setup
CloudWatch Alarm Configuration

A CloudWatch Alarm is arranged to monitor access logs for the website. The alarm is programmed to activate when it detects an abnormal number of failed login attempts.

Configuration of AWS Incident Manager
An incident response plan is formulated in AWS Incident Manager, outlining the actions to be taken when the CloudWatch Alarm is triggered. This plan includes informing the security team via SMS and initiating an AWS Systems Manager Automation runbook to isolate the compromised resources.

Generating Alerts
Activation of the CloudWatch Alarm

The unusual login attempts trigger the CloudWatch Alarm, signaling a potential security incident.

Execution of Response Workflow
Automatic Notification

AWS Incident Manager automatically identifies the CloudWatch Alarm trigger and activates the predefined incident response plan.

The security team is immediately notified via SMS about the security incident.

Integration with Chatbot
AWS Incident Manager integrates with AWS Chatbot, connecting the security team to a designated chat channel.
Team members collaborate in real-time, exchanging information and insights about the incident.

Runbook Execution
The predefined AWS Systems Manager Automation runbook is executed automatically.
The runbook isolates the compromised resources, preventing further unauthorized access.

Tracking Incidents
OpsCenter provides a centralized interface for tracking the incident, documenting actions taken, and collaborating on resolution efforts.
Team members have visibility into the incident's status and can communicate efficiently within the OpsCenter console.

Key Learnings and Best Practices
Automated Incident Response

Incident Manager's automation capabilities enable a rapid and coordinated response to security incidents. Automation ensures that predefined steps are executed promptly, reducing manual intervention and response time.

Collaboration and Communication
Integration with AWS Chatbot facilitates real-time collaboration among team members. Communication channels are established quickly, allowing for effective information sharing and decision-making.

Predefined Runbooks
Creating and utilizing predefined runbooks within AWS Systems Manager ensures consistency in incident response. Runbooks automate tasks such as isolating compromised resources, following security best practices.

OpsCenter for Visibility
OpsCenter provides a centralized and unified view of the incident, helping teams track progress, document actions, and maintain visibility into the incident lifecycle.

Continuous Improvement
After resolving the incident, the organization reviews Incident Manager's post-incident recommendations. This could include automating additional steps in the runbook or enhancing monitoring with new alarms.

Lessons Learned
Proactive Monitoring is Key
Early detection through proactive monitoring, such as CloudWatch Alarms, is crucial for minimizing the impact of security incidents.

Collaboration Streamlines Response
Integrating AWS Chatbot ensures that team members collaborate efficiently during incident response, enhancing communication and decision-making.

Automation Enhances Speed and Consistency
Automated response plans and runbooks significantly reduce response time and ensure consistent execution of predefined steps.

OpsCenter Simplifies Incident Management
Utilizing OpsCenter provides a centralized location for tracking and managing incidents, offering a more streamlined and organized approach to incident resolution.

This example demonstrates how AWS Incident Manager can be a valuable tool in responding to security incidents, underscoring the importance of proactive monitoring, collaboration, and automated incident response workflows. Organizations can adapt these practices to their specific use cases to strengthen their overall incident management strategy in AWS environments.

1. Skenario: Merespons Insiden Keamanan dengan AWS Incident Manager

Situasi:
    Sebuah perusahaan menghosting website di AWS.
    Tim keamanan menyiapkan monitoring menggunakan CloudWatch Alarms untuk mengidentifikasi pola akses tidak biasa.
    Suatu hari, alarm terpicu yang mengindikasikan potensi pelanggaran keamanan.

2. Setup / Konfigurasi Awal
a. CloudWatch Alarm Configuration
    CloudWatch Alarm dikonfigurasi untuk memantau access logs website.
    Alarm diprogram untuk aktif ketika mendeteksi jumlah abnormal percobaan login gagal (failed login attempts).

b. Configuration of AWS Incident Manager
    Rencana respons insiden (incident response plan) dirumuskan di Incident Manager.
    Rencana ini mencakup:
        Memberi tahu tim keamanan melalui SMS.
        Memulai AWS Systems Manager Automation runbook untuk mengisolasi sumber daya yang terkompromi.

3. Generating Alerts / Aktivasi Alarm
    Percobaan login tidak biasa memicu CloudWatch Alarm.
    Alarm menandakan potensi insiden keamanan.

4. Execution of Response Workflow
a. Automatic Notification
    Incident Manager secara otomatis mengidentifikasi pemicu CloudWatch Alarm.
    Mengaktifkan rencana respons insiden yang telah ditentukan sebelumnya.
    Tim keamanan segera diberi tahu melalui SMS tentang insiden keamanan.

b. Integration with Chatbot
    Incident Manager terintegrasi dengan AWS Chatbot.
    Menghubungkan tim keamanan ke saluran chat yang ditentukan.
    Anggota tim berkolaborasi secara real-time, berbagi informasi dan wawasan tentang insiden.

c. Runbook Execution
    Automation runbook yang telah ditentukan sebelumnya dijalankan secara otomatis.
    Runbook mengisolasi sumber daya yang terkompromi, mencegah akses tidak sah lebih lanjut.

d. Tracking Incidents dengan OpsCenter
    OpsCenter menyediakan antarmuka terpusat untuk melacak insiden.
    Mendokumentasikan tindakan yang diambil.
    Berkolaborasi dalam upaya resolusi.
    Anggota tim memiliki visibilitas ke status insiden dan dapat berkomunikasi secara efisien di dalam konsol OpsCenter.

5. Key Learnings and Best Practices
a. Automated Incident Response
    Kemampuan otomatisasi Incident Manager memungkinkan respons yang cepat dan terkoordinasi.
    Otomatisasi memastikan langkah-langkah yang telah ditentukan dijalankan dengan cepat, mengurangi intervensi manual dan waktu respons.

b. Collaboration and Communication
    Integrasi dengan AWS Chatbot memfasilitasi kolaborasi real-time antar anggota tim.
    Saluran komunikasi dibangun dengan cepat, memungkinkan berbagi informasi dan pengambilan keputusan yang efektif.

c. Predefined Runbooks
    Membuat dan menggunakan runbook yang telah ditentukan sebelumnya di Systems Manager memastikan konsistensi dalam respons insiden.
    Runbook mengotomatiskan tugas-tugas seperti mengisolasi sumber daya yang terkompromi, mengikuti praktik terbaik keamanan.

d. OpsCenter for Visibility
    OpsCenter menyediakan tampilan insiden yang terpusat dan terpadu.
    Membantu tim melacak kemajuan, mendokumentasikan tindakan, dan memelihara visibilitas ke dalam siklus hidup insiden.

e. Continuous Improvement
    Setelah menyelesaikan insiden, organisasi meninjau rekomendasi pasca-insiden dari Incident Manager.
    Dapat mencakup mengotomatiskan langkah tambahan dalam runbook atau meningkatkan monitoring dengan alarm baru.

6. Lessons Learned
    Proactive Monitoring is Key → Deteksi dini melalui monitoring proaktif (seperti CloudWatch Alarms) sangat penting untuk meminimalkan dampak insiden keamanan.
    Collaboration Streamlines Response → Integrasi AWS Chatbot memastikan anggota tim berkolaborasi secara efisien selama respons insiden, meningkatkan komunikasi dan pengambilan keputusan.
    Automation Enhances Speed and Consistency → Rencana respons otomatis dan runbook secara signifikan mengurangi waktu respons dan memastikan eksekusi langkah-langkah yang konsisten
    OpsCenter Simplifies Incident Management → Memanfaatkan OpsCenter menyediakan lokasi terpusat untuk melacak dan mengelola insiden, menawarkan pendekatan yang lebih terstruktur dan terorganisir untuk resolusi insiden.
