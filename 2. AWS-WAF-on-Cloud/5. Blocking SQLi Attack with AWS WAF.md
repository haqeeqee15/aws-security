Blocking SQL Injection Attacks with AWS WAF

SQL injection is a malicious technique that exploits vulnerabilities in a web application's database layer. Attackers insert malicious SQL code into input fields or URLs, tricking the application into executing unintended database queries. When successful, these attacks can lead to unauthorized access, data breaches, and even the complete compromise of sensitive information.

For detailed information on Detecting SQL Injection Attacks, you can see the course below:

Here's how AWS WAF filters malicious traffic and provides robust protection against SQL injection:

1. Access AWS WAF Console
     Login to your AWS Management Console and go to the AWS WAF service.

2. Create a Web ACL
      In the AWS WAF console, click on "Web ACLs" in the left navigation pane.
      Click "Create Web ACL" and provide a name for your Web ACL.
     Select the AWS resources (like CloudFront distributions or Application Load Balancers) to which you want to attach the WebACL.

Note : Please check previous sessions for detailed ACL creation.

3. Create a Rule
      Inside the WebACL, click "Add rules" to create a new rule.
     Choose "Create a rule" and select "Contains SQL Injection Attack" on Match Type.

https://app-ld-img.s3.us-east-2.amazonaws.com/training/aws-waf/5.Blocking+SQL+Injection+Attacks+with+AWS+WAF/image5_1.png

4. Configure Rule Actions
     After defining the conditions, specify the actions to be taken when a SQL injection attempt is detected. Common actions include blocking the request, counting the requests, or allowing the request but logging it for further analysis.
     Configure the rate-based settings if you want to limit the number of requests from a client IP address within a specific time frame to prevent brute-force attacks.

https://app-ld-img.s3.us-east-2.amazonaws.com/training/aws-waf/5.Blocking+SQL+Injection+Attacks+with+AWS+WAF/image5_2.png

For this example, the rule action is returning 502 response code and adding a header like: “Blocked: Possible SQL Injection”
5. Review and Activate
     Review your rule configuration and click "Create" to save the rule.
     Once the rule is created, associate it with your WebACL.
     Review the WebACL configuration to ensure that the SQL injection rule is correctly added.
     Click "Activate" to apply the WebACL with the SQL injection rule to the selected AWS resources.

1. Pengertian SQL Injection
    SQL injection adalah teknik berbahaya yang mengeksploitasi kerentanan pada lapisan database aplikasi web.
    Penyerang menyisipkan kode SQL berbahaya ke dalam kolom input atau URL, sehingga aplikasi menjalankan query database yang tidak dimaksudkan.
    Dampak serangan yang berhasil: akses tidak sah, kebocoran data, hingga kompromi total terhadap informasi sensitif.

2. Langkah-Langkah Memfilter Lalu Lintas Berbahaya dengan AWS WAF

Langkah 1 – Akses AWS WAF Console
    Login ke AWS Management Console dan buka layanan AWS WAF.

Langkah 2 – Buat Web ACL
    Di AWS WAF console, klik "Web ACLs" pada panel navigasi kiri.
    Klik "Create Web ACL" dan berikan nama untuk Web ACL.
    Pilih sumber daya AWS (seperti CloudFront distributions atau Application Load Balancers) tempat Anda ingin melampirkan Web ACL.

Catatan: Untuk pembuatan ACL secara detail, lihat sesi sebelumnya.

Langkah 3 – Buat Rule
    Di dalam Web ACL, klik "Add rules" untuk membuat rule baru.
    Pilih "Create a rule" dan pilih "Contains SQL Injection Attack" pada Match Type.

Langkah 4 – Konfigurasi Rule Actions
    Setelah mendefinisikan kondisi, tentukan tindakan yang akan diambil ketika percobaan SQL injection terdeteksi. Tindakan umum: block request, count request, atau allow request tetapi dicatat untuk analisis lebih lanjut.
    Konfigurasi pengaturan berbasis rate (rate-based settings) jika ingin membatasi jumlah request dari alamat IP klien dalam jangka waktu tertentu untuk mencegah brute-force attacks.

Contoh dari materi:
Untuk contoh ini, rule action mengembalikan kode respons 502 dan menambahkan header seperti: "Blocked: Possible SQL Injection".

Langkah 5 – Tinjau dan Aktifkan
    Tinjau konfigurasi rule dan klik "Create" untuk menyimpan rule.
    Setelah rule dibuat, kaitkan dengan Web ACL.
    Tinjau konfigurasi Web ACL untuk memastikan rule SQL injection telah ditambahkan dengan benar.
    Klik "Activate" untuk menerapkan Web ACL dengan rule SQL injection ke sumber daya AWS yang dipilih.

3. Hasil Setelah Aktivasi
    Setelah mengaktifkan dan melakukan contoh serangan SQL injection, kita dapat melihat log seperti yang ditampilkan pada screenshot di materi.
