VPC Flow Logs

VPC Flow Logs is a useful function allowing you to gather details on the IP traffic moving between network interfaces within your VPC. The data from flow logs can be sent to various destinations, such as Amazon CloudWatch Logs, Amazon S3, or Amazon Kinesis Data Firehose. Once a flow log is established, you can access and review the log records in the group, bucket, or stream you've set up.

Flow logs serve several purposes, including:
1. Identifying issues with extremely restrictive security group rules
2. Monitoring the traffic reaching your instance
3. Understanding the direction of traffic to and from network interfaces

It's essential to note that flow log data is collected independently from the path of your network traffic. Therefore, it has no impact on network throughput or latency. Creating or deleting flow logs does not pose any risk to network performance. You can create a flow log for a VPC, a subnet, or a network interface. If you create flow logging for a subnet or VPC, every network interface in that subnet or VPC is monitored.

To generate a flow log, you need to provide;

    Source from which to create the flow log
    Type of traffic to capture (accepted traffic, rejected traffic, or all traffic)
    Destinations to which you want to publish flow log data

Let’s see some flow log examples;                    

"2 eni-0d14a8f66abcd1234 172.31.16.21 203.0.113.10 49234 443 6 10 3210 1637044452 1637044512 REJECT OK"

    2 : Represents the version of the flow log record.
    eni-0d14a8f66abcd1234 : Network interface ID associated with the traffic.
    172.31.16.21 : Source IP address.
    203.0.113.10 : Destination IP address.
    49234 : Source port.
    443 : Destination port.
    6 : IP protocol number (6 represents TCP).
    10 : Action (10 is "REJECT" indicating the traffic was rejected).
    3210 : Number of bytes sent from source to destination.
    1637044452 : Start time of the flow log record in Unix timestamp format.
    1637044512 : End time of the flow log record in Unix timestamp format.
    REJECT OK : Status of the flow log record, indicating that the traffic was rejected.

    2 : Version of the flow log record.

Use Cases and Benefits
VPC Flow Logs have various uses, covering aspects like security, compliance, troubleshooting, and performance optimization. The process of compliance audits is made more efficient with detailed records of network activity. Administrators find it easier to troubleshoot network issues as they gain insights into traffic patterns and possible bottlenecks. Additionally, understanding how resources interact within the VPC provides valuable information for efforts to optimize performance.

1. Definisi VPC Flow Logs
    VPC Flow Logs adalah fungsi yang memungkinkan pengumpulan informasi detail tentang lalu lintas IP yang bergerak antar network interfaces di dalam VPC.
    Data flow logs dapat dikirim ke tiga tujuan: Amazon CloudWatch Logs, Amazon S3, atau Amazon Kinesis Data Firehose.
    Setelah flow log dibuat, Anda dapat mengakses dan meninjau log records di grup, bucket, atau stream yang telah disiapkan.

2. Tujuan Penggunaan Flow Logs
    Mengidentifikasi masalah dengan aturan security group yang sangat restriktif.
    Memantau lalu lintas yang mencapai instance.
    Memahami arah lalu lintas (direction of traffic) ke dan dari network interfaces.

3. Karakteristik Penting Flow Logs
    Data flow log dikumpulkan secara independen dari jalur lalu lintas jaringan, sehingga tidak ada dampak terhadap network throughput atau latency.
    Membuat atau menghapus flow logs tidak menimbulkan risiko terhadap kinerja jaringan.
    Anda dapat membuat flow log untuk VPC, subnet, atau network interface.
    Jika Anda membuat flow logging untuk subnet atau VPC, maka setiap network interface di subnet atau VPC tersebut akan dimonitor.

4. Persyaratan untuk Membuat Flow Log
    Source – sumber dari mana flow log akan dibuat.
    Type of traffic – jenis lalu lintas yang akan ditangkap (accepted traffic, rejected traffic, atau all traffic).
    Destinations – tujuan di mana Anda ingin mempublikasikan data flow log.

5. Contoh Flow Log Record dan Penjelasan Field
Contoh record:
2 eni-0d14a8f66abcd1234 172.31.16.21 203.0.113.10 49234 443 6 10 3210 1637044452 1637044512 REJECT OK

Penjelasan field:
    Version = 2 (versi record flow log)
    ENI ID = eni-0d14a8f66abcd1234 (ID network interface yang terkait dengan lalu lintas)
    Source IP = 172.31.16.21 (alamat IP sumber)
    Destination IP = 203.0.113.10 (alamat IP tujuan)
    Source Port = 49234 (port sumber)
    Destination Port = 443 (port tujuan, ini untuk HTTPS)
    Protocol = 6 (nomor protokol IP, 6 berarti TCP)
    Action = 10 (tindakan, 10 berarti REJECT atau lalu lintas ditolak)
    Bytes = 3210 (jumlah byte yang dikirim dari sumber ke tujuan)
    Start Time = 1637044452 (waktu mulai dalam format Unix timestamp)
    End Time = 1637044512 (waktu akhir dalam format Unix timestamp)
    Status = REJECT OK (lalu lintas ditolak)
