Key Components of Amazon VPC

Subnets

Subnets are segmented IP address ranges within a VPC, enabling you to logically segment your VPC's IP address space to isolate resources.
![1](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_1.png)

(Image Source: https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html )                             

Purpose
Resource Segregation : Group similar resources together.
Traffic Control : Define access and control between resources.
High Availability : Distribute resources across different availability zones for fault tolerance.

Key Points
Public vs. Private Subnets : Public subnets have a route to an internet gateway, allowing resources to connect to the internet whereas private subnets do not have direct internet access.
CIDR Blocks : Classless Inter-Domain Routing blocks define the IP address range for a subnet.
Availability Zones : Subnets should span multiple availability zones for redundancy and fault tolerance.

Route Tables
Route tables in AWS VPCs control the routing of network traffic between subnets, internet gateways, virtual private gateways, and other connected networks.

Purpose
Traffic Direction : Manage the flow of incoming and outgoing traffic within the VPC and beyond.
Connectivity : Establish paths for communication between different network components.
Routing Decisions : Outline how traffic is forwarded based on defined rules.

Key Points
Association : Subnets are associated with specific route tables.
Default vs. Custom Route Tables : Default route tables are automatically created; custom route tables offer greater control.
Routing Priority : Routes are evaluated based on the most specific match.

Route Table Configuration
1. Default Route :
0.0.0.0/0 Route : Typically used for internet-bound traffic, directing it to an internet gateway.
Custom Routes : Define specific destinations for specialized traffic management.
![2](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_2.png)

2. Routing Priority :
Route Evaluation Order : Route evaluation is determined by specificity; routes with greater specificity are prioritized.
Implicit vs. Explicit Routes : Implicit local routes for VPC CIDR blocks and explicit custom routes.
![3](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_3.png)
(Image Source: https://docs.aws.amazon.com/ )

Network Access Control Lists (NACLs)
NACLs in AWS are stateless network-level security measures applied at the subnet level to control inbound and outbound traffic.

A network access control list (ACL) regulates specific inbound or outbound traffic at the subnet level within your VPC. You have the option to use the default network ACL provided for your VPC, or you can create a custom network ACL. This custom ACL enables you to implement rules akin to those applied in your security groups, enhancing the overall security measures within your VPC.
![4](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_4.png)
(Image Source: https://docs.aws.amazon.com/vpc/latest/userguide/vpc-network-acls.html )

Purpose
Traffic Filtering : Control inbound and outbound traffic based on defined rules.
Subnet Level Security : Provide an additional layer of defense at the network level.
Complement Security Groups : Offer broader control over traffic.

Key Points
Rule Evaluation : Rules are processed in an order from lowest to highest number.
Allow/Deny Rules : Specify rules to accept or deny traffic based on protocols, ports, and IP addresses.
Stateless Nature : Unlike security groups, NACLs do not track the state of connections.

Default Network ACL Configuration

The default network ACL is set to permit unrestricted traffic both entering and leaving the subnets it's linked to. Additionally, it contains a catch-all rule marked with an asterisk (*), ensuring that any packet failing to meet the criteria of preceding rules will be denied passage. Importantly, this specific rule remains unmodifiable or removable.
![5](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_5.png)
![6](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_6.png)

Security Groups
Security Groups in AWS act as virtual firewalls for EC2 instances and control inbound and outbound traffic at the instance level.


Upon VPC creation, a default security group is provided. For enhanced control, additional security groups can be generated within the VPC, each having distinct inbound and outbound rules. Inbound rules allow specification of source, port range, and protocol, while outbound rules permit defining destination, port range, and protocol for traffic.
![7](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_7.png)
(Image Source: https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html )

Purpose
Instance-Level Security : Regulate traffic for specific instances based on defined rules.
Stateful Filtering : Track the state of connections and allow return traffic automatically.
Ease of Management : Apply and manage rules for multiple instances collectively.

Key Points
1. Stateful Nature :
Connection Tracking : Automatically permits return traffic for allowed inbound connections.
Simplicity : Create rules for allowing specific traffic without considering return traffic explicitly.

2. Inbound and Outbound Rules :
Inbound Rules : Regulate inbound traffic to instances by specifying protocols, ports, and source IP addresses.
Outbound Rules : Regulate outgoing traffic from instances to external destinations.
![8](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_1.png)
(Image Source: https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html )

NAT Gateways
NAT Gateways in AWS provide outbound internet connectivity for instances within private subnets while offering enhanced security through managing traffic initiated by the instances.

NAT Gateway Connectivity Types
Public Connectivity
Usage : Allows instances in private subnets to access the internet via a public NAT gateway.
Configuration : Created in a public subnet,  this requires an associated Elastic IP address.
Routing : Directs traffic from the NAT gateway to the VPC's internet gateway for internet access.
Additional Use : It can facilitate connections to other VPCs or on-premises networks via transit or virtual private gateways.

Private Connectivity
Usage : Enables instances in private subnets to connect to other VPCs or on-premises networks.
Configuration : Implemented without an associated Elastic IP address.
Routing : Routes traffic through transit or virtual private gateways; however, direct internet access is restricted.
Limitation : Simultaneously attaching an internet gateway and a private NAT gateway results in dropped traffic from the NAT gateway to the internet.

Purpose
Outbound Internet Access : Facilitate instances in private subnets to access the internet for updates, patches, and external services.
Security Enhancement : Restrict inbound traffic by default, allowing initiated outbound traffic only.
Scalability and High Availability : Automatically scale to meet demand and ensure high availability.

Key Points
1. Outbound Traffic Management :
Elastic IP Association : NAT Gateways are associated with Elastic IPs for outbound traffic initiation.
Stateful Traffic : Track the state of outbound connections, allowing return traffic for initiated connections.

2. Subnet Integration :
Private Subnet Association : Use NAT Gateways within private subnets to manage outbound traffic.
Routing Configuration : Update route tables to direct outbound traffic through NAT Gateways.
![9](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_9.png)
(Image Source: https://docs.aws.amazon.com/ )

Internet Gateways
An internet gateway, a highly available and horizontally scalable component within a VPC, facilitates communication between your VPC and the internet. It effectively supports both IPv4 and IPv6 traffic without imposing any risks to availability or limitations on network bandwidth.

The internet gateway allows connectivity between resources within your public subnets, like EC2 instances, and the internet when those resources possess either a public IPv4 or IPv6 address. Likewise, it accepts incoming connections from internet-based resources to your subnet using the public IPv4 or IPv6 address. For instance, it facilitates accessing an AWS EC2 instance from your local computer.
![10](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_10.png)
(Image Source: https://docs.aws.amazon.com/ )

The instances in the public subnet must have public IP addresses or Elastic IP addresses to enable communication with the internet over the internet gateway. 

Purpose
Internet Connectivity : Acts as a gateway, enabling resources within a VPC to access the internet and vice versa.
IPv4 and IPv6 Support : Supports both IPv4 and IPv6 traffic for seamless communication.
Network Traffic Management : Facilitates unrestricted traffic flow between the VPC and the internet.

Key Points
Attachment to VPC : Each VPC can have only one internet gateway attached.
Route Table Association : Explicitly associate the internet gateway with the route table for public subnets.
Security Considerations : Carefully manage access to ensure secure communication.

Virtual Private Gateways
Virtual Private Gateways in AWS establish secure and encrypted connections between VPCs, on-premises data centers, or remote networks using VPN connections.

Purpose
Secure Communication : Enable encrypted communication between different networks.
Hybrid Cloud Connectivity : Facilitate connections between on-premises data centers and AWS resources.
Cross-Account VPC Peering : Connect VPCs across different AWS accounts securely.

Key Points
VPN Connections and IPSec Tunnels : Create secure tunnels for data transmission.
Integration with On-Premises Networks : Use VPN connections to establish connectivity with existing infrastructure.
Cross-Account VPC Peering : Establish connections between VPCs in different accounts securely.
![11](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_11.png)

Understanding these components is important for designing secure, and efficiently functioning VPC architectures in AWS. They provide the framework for controlling network traffic, securing resources, and enabling connectivity within the cloud environment.

Creating Security Groups
By default, when you create a new security group, it initially allows all traffic to leave the resource through an outbound rule. To enable inbound traffic or restrict outbound traffic, you need to add specific rules.

To make a security group using the console:
    Go to the Amazon VPC console at https://console.aws.amazon.com/vpc/ .
    In the side menu, select "Security groups."
![12](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_12.png)

    Click on "Create security group."
    Provide a name and description for the security group. Keep in mind that you can't change this information after the group is created.
![13](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_13.png)

    From the VPC dropdown, choose the VPC where you want to use the security group. Each security group is specific to the VPC it's created in.
![14](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_14.png)

    At this point, you can add security group rules now or later.
    Tags can also be added now or later. To add a tag, select "Add new tag" and enter the tag key and value.
    Finally, click on "Create security group."
![15](https://app-ld-img.s3.us-east-2.amazonaws.com/training/Amazon+Virtual+Private+Cloud+(VPC)/2.Key+Components+of+Amazon+VPC/image2_15.png)

Once the security group is created, you can assign it to an EC2 instance during the instance launch or change the currently assigned security group. 

1. Subnets
Definisi
    Subnets adalah rentang alamat IP yang tersegmentasi di dalam VPC.
    Memungkinkan segmentasi logis ruang alamat IP VPC untuk mengisolasi sumber daya.

Tujuan
    Resource Segregation: Mengelompokkan sumber daya yang serupa.
    Traffic Control: Mendefinisikan akses dan kontrol antar sumber daya.
    High Availability: Mendistribusikan sumber daya di berbagai availability zones untuk toleransi kesalahan.

Poin Penting
    Public vs Private Subnets: Public subnet memiliki route ke internet gateway (koneksi internet langsung). Private subnet tidak memiliki akses internet langsung.
    CIDR Blocks: Mendefinisikan rentang alamat IP untuk subnet.
    Availability Zones: Subnets harus mencakup beberapa availability zones untuk redundansi dan toleransi kesalahan.

2. Route Tables
Definisi
    Route tables mengontrol routing lalu lintas jaringan antara subnet, internet gateway, virtual private gateway, dan jaringan terhubung lainnya.

Tujuan
    Traffic Direction: Mengelola alur lalu lintas masuk dan keluar dalam VPC dan sekitarnya.
    Connectivity: Membangun jalur komunikasi antara komponen jaringan yang berbeda.
    Routing Decisions: Menentukan bagaimana lalu lintas diteruskan berdasarkan aturan yang didefinisikan.

Poin Penting
    Association: Subnets dikaitkan dengan route tables tertentu.
    Default vs Custom Route Tables: Default route tables dibuat otomatis; custom route tables menawarkan kontrol lebih besar.
    Routing Priority: Route dievaluasi berdasarkan pencocokan paling spesifik.

Konfigurasi Route Table
    Default Route (0.0.0.0/0): Biasanya untuk lalu lintas menuju internet, diarahkan ke internet gateway.
    Custom Routes: Mendefinisikan tujuan spesifik untuk manajemen lalu lintas khusus.
    Routing Priority: Route dengan spesifisitas lebih tinggi diprioritaskan.
    Implicit vs Explicit Routes: Implicit local routes untuk VPC CIDR blocks dan explicit custom routes.

3. Network Access Control Lists (NACLs)
Definisi
    NACLs adalah langkah-langkah keamanan tingkat jaringan yang bersifat stateless, diterapkan di tingkat subnet untuk mengontrol lalu lintas masuk dan keluar.
    Anda dapat menggunakan default network ACL atau membuat custom network ACL.

Tujuan
    Traffic Filtering: Mengontrol lalu lintas inbound dan outbound berdasarkan aturan yang didefinisikan.
    Subnet Level Security: Memberikan lapisan pertahanan tambahan di tingkat jaringan.
    Complement Security Groups: Menawarkan kontrol yang lebih luas atas lalu lintas.

Poin Penting
    Rule Evaluation: Aturan diproses dari nomor terendah ke tertinggi.
    Allow/Deny Rules: Aturan untuk menerima atau menolak lalu lintas berdasarkan protokol, port, dan alamat IP.
    Stateless Nature: NACLs tidak melacak status koneksi (berbeda dengan security groups).

Default Network ACL Configuration
    Default network ACL mengizinkan lalu lintas tidak terbatas baik masuk maupun keluar dari subnet yang terhubung.
    Mengandung aturan catch-all (tanda *) yang menolak paket yang tidak memenuhi kriteria aturan sebelumnya.
    Aturan catch-all ini tidak dapat diubah atau dihapus.

4. Security Groups
Definisi
    Security Groups bertindak sebagai virtual firewall untuk EC2 instances.
    Mengontrol lalu lintas inbound dan outbound di tingkat instance.

Tujuan
    Instance-Level Security: Mengatur lalu lintas untuk instance tertentu.
    Stateful Filtering: Melacak status koneksi dan mengizinkan return traffic secara otomatis.
    Ease of Management: Menerapkan dan mengelola aturan untuk banyak instance secara kolektif.

Poin Penting
    Stateful Nature: Otomatis mengizinkan return traffic untuk koneksi inbound yang diizinkan. Tidak perlu aturan eksplisit untuk return traffic.
    Inbound Rules: Mengatur lalu lintas masuk ke instance (protokol, port, source IP).
    Outbound Rules: Mengatur lalu lintas keluar dari instance ke tujuan eksternal.

5. NAT Gateways
Definisi
    NAT Gateways menyediakan konektivitas internet outbound untuk instance di private subnets.
    Meningkatkan keamanan melalui manajemen lalu lintas yang diprakarsai oleh instance.

Jenis Konektivitas NAT Gateway
Public Connectivity
    Penggunaan: Memungkinkan instance di private subnets mengakses internet.
    Konfigurasi: Dibuat di public subnet, memerlukan Elastic IP address.
    Routing: Mengarahkan lalu lintas dari NAT gateway ke internet gateway.
    Tambahan: Dapat memfasilitasi koneksi ke VPC lain atau on-premises via transit/virtual private gateways.

Private Connectivity
    Penggunaan: Memungkinkan instance di private subnets terhubung ke VPC lain atau on-premises networks.
    Konfigurasi: Tidak memerlukan Elastic IP address.
    Routing: Melalui transit atau virtual private gateways. Akses internet langsung dibatasi.
    Keterbatasan: Memasang internet gateway dan private NAT gateway secara bersamaan akan membuat lalu lintas dari NAT gateway ke internet terputus.

Tujuan
    Outbound Internet Access: Akses internet untuk update, patch, dan layanan eksternal.
    Security Enhancement: Membatasi inbound traffic secara default.
    Scalability and High Availability: Otomatis berskala dan ketersediaan tinggi.

Poin Penting
    Outbound Traffic Management: NAT Gateway dikaitkan dengan Elastic IPs. Bersifat stateful.
    Subnet Integration: Gunakan NAT Gateway di dalam private subnets. Perbarui route tables untuk mengarahkan outbound traffic melalui NAT Gateway.

6. Internet Gateways
Definisi
    Internet gateway adalah komponen VPC yang highly available dan horizontally scalable.
    Memfasilitasi komunikasi antara VPC dan internet.
    Mendukung IPv4 dan IPv6 tanpa risiko ketersediaan atau batasan bandwidth.

Fungsi
    Memungkinkan konektivitas antara resource di public subnets (EC2 instances) dan internet, selama resource tersebut memiliki public IPv4 atau IPv6 address.
    Menerima koneksi masuk dari internet ke subnet menggunakan public IPv4 atau IPv6 address.
    Contoh: mengakses EC2 instance dari komputer lokal

Poin Penting
    Attachment ke VPC: Setiap VPC hanya dapat memiliki satu internet gateway.
    Route Table Association: Internet gateway harus secara eksplisit dikaitkan dengan route table untuk public subnets.
    Security Considerations: Akses harus dikelola dengan hati-hati.
    Instance di public subnet harus memiliki public IP addresses atau Elastic IP addresses untuk komunikasi dengan internet melalui internet gateway.

7. Virtual Private Gateways
Definisi
    Virtual Private Gateways membangun koneksi aman dan terenkripsi antara VPC, pusat data on-premises, atau jaringan jarak jauh menggunakan VPN connections.

Tujuan
    Secure Communication: Komunikasi terenkripsi antar jaringan berbeda.
    Hybrid Cloud Connectivity: Koneksi antara pusat data on-premises dan resource AWS.
    Cross-Account VPC Peering: Menghubungkan VPC di berbagai akun AWS secara aman.

Poin Penting
    VPN Connections dan IPSec Tunnels: Membuat tunnel aman untuk transmisi data.
    Integration with On-Premises Networks: Menggunakan VPN connections untuk konektivitas dengan infrastruktur yang sudah ada.
    Cross-Account VPC Peering: Koneksi antar VPC di akun berbeda secara aman.

8. Membuat Security Groups (Langkah-langkah)
    Buka Amazon VPC console di https://console.aws.amazon.com/vpc/.
    Di menu samping, pilih "Security groups".
    Klik "Create security group".
    Berikan name dan description untuk security group (tidak dapat diubah setelah dibuat).
    Dari dropdown VPC, pilih VPC tempat security group akan digunakan (setiap security group spesifik untuk VPC tempatnya dibuat).
    Anda dapat menambahkan aturan security group sekarang atau nanti.
    Tags juga dapat ditambahkan sekarang atau nanti (klik "Add new tag", masukkan tag key dan value).
    Klik "Create security group".

Catatan Penting:
    Secara default, security group baru mengizinkan semua lalu lintas keluar (outbound).
    Untuk mengizinkan inbound traffic atau membatasi outbound traffic, Anda perlu menambahkan aturan spesifik.
    Setelah security group dibuat, Anda dapat menetapkannya ke EC2 instance saat peluncuran instance atau mengubah security group yang sedang ditetapkan.
