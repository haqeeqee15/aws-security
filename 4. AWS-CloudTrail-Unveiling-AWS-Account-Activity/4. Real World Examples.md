Real World Examples

In the realm of cloud services monitoring, AWS CloudTrail stands as a critical component. It offers well-documented logs streamed in JSON format, simplifying the parsing and extraction of fields within Security Information and Event Management (SIEM) systems. While this guide focuses on Splunk, the principles discussed can also be adapted to other SIEM platforms.

Most SIEM platforms offer apps or connectors for ingesting AWS CloudTrail logs. For Splunk, you'll likely need the Splunk Add-on for Amazon Web Services (for data ingestion) and the Splunk app for AWS (for interpreting data and providing pre-built dashboards). If your solution lacks dedicated apps, you can script log pulling via the CloudTrail API, given the logs' JSON format.

CloudTrail records AWS Management Console events under the signin.amazonaws.com event source, allowing us to observe and oversee user sign-in activities. This feature helps identify and address potential security concerns. Here are some examples of how to spot problems within these sign-in logs.

To determine the success or failure of a sign-in attempt, you can search for `ConsoleLogin` events in the `eventName` field within AWS CloudTrail logs. These events contain all sign-in activities through the AWS Management Console. The `userName` field contains the user's name associated with the event, while `responseElements.ConsoleLogin` indicates "Failure" for unsuccessful sign-in attempts and "Success" for successful ones. Additional fields like `additionalEventData.MFAUsed` indicate whether Multi-Factor Authentication (MFA) was utilized, and `userIdentity.type` specifies if the user is a Root user or an IAM user.

Consider a scenario where you want to retrieve login events (ConsoleLogin) from your AWS CloudTrail data lake. The following SQL query demonstrates how you can filter specific fields from the data lake for analysis:

SELECT
    eventTime,
    userIdentity.arn AS user,
    awsRegion,
    userAgent,
    sourceIPAddress,
    eventName

FROM
    c24f64a9-219e-4fb5-8deb-c856874ede7d

WHERE
    awsRegion IN ('us-east-1', 'us-west-2')
    AND eventName = 'ConsoleLogin'
    AND eventTime > '2023-10-14 00:00:00'
                  

In this example, the query fetches 'ConsoleLogin' events after '2023-10-14 00:00:00' from the specified AWS regions ('us-east-1' and 'us-west-2'). The selected fields include the event timestamp (eventTime), user identity (userIdentity.arn), AWS region (awsRegion), user agent (userAgent), source IP address (sourceIPAddress), and event name (eventName).

    Attempts to brute-force login credentials.
    Instances where users log in without Multi-Factor Authentication (MFA).
    Successful logins originating from countries not previously recorded.

SELECT
    sourceIPAddress,
    errorMessage,
    responseElements

FROM
    c24f64a9-219e-4fb5-8deb-c856874ede7d

WHERE
    eventName = 'ConsoleLogin'

                  
The provided SQL query selects the sourceIPAddress, errorMessage, and responseElements fields from the AWS CloudTrail data lake table where the eventName is 'ConsoleLogin'. This query will return specific information about console login events, including the IP address, error message, and response elements related to those events.

Please note that the table name “c24f64a9-219e-4fb5-8deb-c856874ede7d” should be replaced with the actual name of your CloudTrail table in your AWS environment. Additionally, ensure that the fields you are selecting (sourceIPAddress, errorMessage, and responseElements) exist in your CloudTrail data.

1. CloudTrail dalam Monitoring Layanan Cloud
    CloudTrail menyediakan log yang terstruktur dengan baik (well-documented logs) dalam format JSON.
    Memudahkan parsing dan ekstraksi field dalam sistem SIEM (Security Information and Event Management).
    Materi menggunakan Splunk sebagai contoh, tetapi prinsip yang dibahas dapat diadaptasi ke platform SIEM lainnya.

Integrasi dengan SIEM:
    Sebagian besar platform SIEM memiliki apps atau connectors untuk mengonsumsi log CloudTrail.
    Untuk Splunk: Splunk Add-on for Amazon Web Services (untuk ingestion data) dan Splunk app for AWS (untuk interpretasi data dan dashboard bawaan).
    Jika tidak memiliki app khusus: scripting melalui CloudTrail API dapat dilakukan karena format log JSON.

2. Monitoring Sign-In Activities
    CloudTrail mencatat event AWS Management Console di bawah event source signin.amazonaws.com.
    Hal ini memungkinkan kita mengamati dan mengawasi aktivitas sign-in pengguna.

Field-field penting untuk menentukan keberhasilan login:
    eventName = ConsoleLogin → semua aktivitas sign-in melalui AWS Management Console.
    userName → nama pengguna yang terkait dengan event.
    responseElements.ConsoleLogin → "Failure" (gagal) atau "Success" (berhasil).
    additionalEventData.MFAUsed → menunjukkan apakah MFA digunakan atau tidak.
    userIdentity.type → menunjukkan apakah pengguna adalah Root user atau IAM user.

3. Contoh Query SQL untuk Menganalisis CloudTrail
Query 1 - Mendapatkan login events (ConsoleLogin) setelah tanggal tertentu di region tertentu:
sql

SELECT
    eventTime,
    userIdentity.arn AS user,
    awsRegion,
    userAgent,
    sourceIPAddress,
    eventName
FROM
    c24f64a9-219e-4fb5-8deb-c856874ede7d
WHERE
    awsRegion IN ('us-east-1', 'us-west-2')
    AND eventName = 'ConsoleLogin'
    AND eventTime > '2023-10-14 00:00:00'

Field yang dipilih: eventTime, user (dari userIdentity.arn), awsRegion, userAgent, sourceIPAddress, eventName.

Query 2 - Mendapatkan sourceIPAddress, errorMessage, dan responseElements untuk event ConsoleLogin:
sql

SELECT
    sourceIPAddress,
    errorMessage,
    responseElements
FROM
    c24f64a9-219e-4fb5-8deb-c856874ede7d
WHERE
    eventName = 'ConsoleLogin'

Catatan: Nama tabel (c24f64a9-219e-4fb5-8deb-c856874ede7d) harus diganti dengan nama tabel CloudTrail yang sebenarnya di lingkungan AWS.

4. Informasi dari Field yang Dipilih
    sourceIPAddress → Alamat IP dari mana upaya autentikasi dilakukan (contoh: 217.131.99.238).
    errorMessage → Menunjukkan apakah upaya autentikasi berhasil atau gagal, dan penyebab kegagalan jika gagal (contoh: "Failed authentication").
    responseElements → Detail tambahan tentang upaya autentikasi, termasuk jenis operasi login dan hasilnya.

5. Contoh Analisis Hasil
Berdasarkan hasil query (contoh di materi):
    Terdapat beberapa upaya autentikasi dari alamat IP 217.131.99.238.
    Empat upaya pertama gagal dengan alasan "Failed authentication".
    Dua upaya terakhir berhasil, ditunjukkan dengan "ConsoleLogin=Success" di field responseElements.

6. Ancaman dan Serangan yang Dapat Diidentifikasi
Dengan menganalisis event ConsoleLogin, Anda dapat memantau dan mengidentifikasi berbagai ancaman keamanan dan serangan yang berhasil, termasuk:
    Attempts to brute-force login credentials (upaya brute force terhadap kredensial login).
    Instances where users log in without Multi-Factor Authentication (MFA) (pengguna login tanpa MFA).
    Successful logins originating from countries not previously recorded (login berhasil dari negara yang belum pernah tercatat sebelumnya).
    Successful logins from known malicious IP addresses (login berhasil dari alamat IP berbahaya yang dikenal).
