Configuring Data Sources
One of GuardDuty's key features is its ability to analyze various data sources to detect potential security threats. In this course, we'll take a closer look at how GuardDuty utilizes different AWS data sources and its analysis process.

AWS CloudTrail Event Logs
AWS CloudTrail provides a detailed history of API calls made within your AWS account, including calls made via AWS Management Console, SDKs, command line tools, and certain AWS services. GuardDuty monitors these CloudTrail event logs, identifying users, accounts, and source IP addresses for API calls. It processes these logs for profiling and anomaly detection while ensuring data security through encryption.

CloudTrail Management Events
GuardDuty also monitors CloudTrail management events, offering insight into management operations performed on your AWS resources. Examples of such events include configuring security settings (IAM AttachRolePolicyAPI operations), setting up routing rules (Amazon EC2 CreateSubnet API operations), and enabling logging (AWS CloudTrail CreateTrail API operations). GuardDuty analyzes these events to identify any unusual or unauthorized activities.

VPC Flow Logs
VPC Flow Logs capture information about IP traffic to and from network interfaces attached to Amazon EC2 instances. GuardDuty analyzes these flow logs, processing the data independently without altering your existing flow logs configuration. This analysis helps GuardDuty detect potential threats within your AWS environment.

GuardDuty Lambda Protection
GuardDuty offers optional Lambda Protection, enhancing security for your AWS Lambda functions. It monitors Lambda Network Activity, including VPC flow logs, ensuring comprehensive coverage against security threats. By configuring Lambda Protection, you can safeguard your Lambda functions effectively.

GuardDuty EKS Protection
When EKS Runtime Monitoring is enabled, GuardDuty analyzes VPC Flow Logs from EKS EC2 nodes, providing unique threat detection capabilities. This continuous coverage helps GuardDuty detect and mitigate security risks effectively. GuardDuty ensures there are no additional charges if runtime events are received from EKS EC2 nodes.

DNS Logs
GuardDuty can access and process DNS logs if you use AWS DNS resolvers for your Amazon EC2 instances. It analyzes request and response DNS logs through internal AWS DNS resolvers, offering insights into DNS-related activities. Note that if you use third-party DNS resolvers or set up custom DNS resolvers, GuardDuty cannot access data from this source.

In summary, GuardDuty's ability to monitor and analyze these diverse data sources empowers you to maintain a secure AWS environment. By leveraging the service's capabilities and understanding its data sources, you can proactively protect your AWS assets from potential security threats.

GuardDuty accesses all of these data sources without any of them having to be enabled; although it is a best practice to enable CloudTrail and VPC Flow Logs for your analysis.

Customizing Detector Settings

Customizing detector settings allows you to tailor GuardDuty's behavior to your specific security requirements.

Adjusting Threat Intelligence Feeds : GuardDuty integrates with external threat intelligence feeds. Customize which feeds you want GuardDuty to use based on your organization's threat profile.

Setting Finding Thresholds : Configure finding thresholds to adjust the sensitivity of GuardDuty. Fine-tune these settings to receive findings based on your desired level of confidence in the detected threats.

Notification and Alert Settings : Specify the AWS S3 bucket and SNS topic for storing findings and receiving notifications. Configure these settings to ensure that your security team is promptly alerted when GuardDuty detects suspicious activities.

User Permission Settings : Define IAM (Identity and Access Management) roles and permissions for GuardDuty users. Ensure that appropriate team members have the necessary access to view findings and respond to incidents.

Automated Responses : Explore automated response options, such as integrating GuardDuty findings with AWS Lambda functions. This allows you to automate responses to specific types of security threats, enhancing your incident response capabilities.

1. Langkah-Langkah Mengaktifkan GuardDuty (Enabling GuardDuty)
    Sign in to AWS Management Console → Login dengan kredensial AWS Anda.
    Navigate to GuardDuty → Buka layanan GuardDuty di AWS Management Console.
    Enable GuardDuty → Klik tombol "Enable GuardDuty" untuk mengaktifkan GuardDuty di akun AWS Anda.
    Select AWS Regions → Pilih wilayah (region) AWS tempat GuardDuty akan memonitor sumber daya Anda. Anda dapat mengaktifkan GuardDuty di region tertentu berdasarkan kebutuhan.
    Confirm and Enable → Tinjau konfigurasi, konfirmasi, dan aktifkan GuardDuty. Layanan akan mulai menganalisis data dan menghasilkan temuan (findings) berdasarkan region yang dipilih.

2. Konfigurasi Sumber Data (Configuring Data Sources)
GuardDuty menganalisis berbagai sumber data untuk mendeteksi potensi ancaman keamanan.
a. AWS CloudTrail Event Logs
    Memberikan riwayat detail panggilan API di dalam akun AWS (termasuk via Management Console, SDKs, command line tools, dan layanan AWS tertentu).
    GuardDuty memantau log ini, mengidentifikasi pengguna, akun, dan alamat IP sumber untuk panggilan API.
    Memproses log untuk profiling dan deteksi anomali dengan menjaga keamanan data melalui enkripsi.

b. CloudTrail Management Events
    Memberikan wawasan tentang operasi manajemen yang dilakukan pada sumber daya AWS.
    Contoh event: mengonfigurasi pengaturan keamanan (IAM AttachRolePolicy API operations), menyiapkan aturan routing (Amazon EC2 CreateSubnet API operations), mengaktifkan logging (AWS CloudTrail CreateTrail API operations).
    GuardDuty menganalisis event ini untuk mengidentifikasi aktivitas tidak biasa atau tidak sah.

c. VPC Flow Logs
    Menangkap informasi tentang lalu lintas IP ke dan dari network interfaces yang terpasang pada Amazon EC2 instances.
    GuardDuty menganalisis flow logs secara independen tanpa mengubah konfigurasi flow logs yang sudah ada.
    Analisis ini membantu GuardDuty mendeteksi potensi ancaman di lingkungan AWS.

d. GuardDuty Lambda Protection
    Fitur opsional yang meningkatkan keamanan untuk AWS Lambda functions.
    Menonitor Network Activity dari Lambda, termasuk VPC flow logs.
    Memberikan cakupan komprehensif terhadap ancaman keamanan.

e. GuardDuty EKS Protection
    Ketika EKS Runtime Monitoring diaktifkan, GuardDuty menganalisis VPC Flow Logs dari EKS EC2 nodes.
    Memberikan kemampuan deteksi ancaman yang unik.
    Tidak ada biaya tambahan jika runtime events diterima dari EKS EC2 nodes.

f. DNS Logs
    GuardDuty dapat mengakses dan memproses DNS logs jika Anda menggunakan AWS DNS resolvers untuk Amazon EC2 instances.
    Menganalisis request dan response DNS logs melalui internal AWS DNS resolvers.
    Catatan penting: Jika Anda menggunakan DNS resolver pihak ketiga atau DNS resolver kustom, GuardDuty tidak dapat mengakses data dari sumber ini.

3. Catatan Penting tentang Sumber Data
    GuardDuty dapat mengakses semua sumber data ini tanpa perlu diaktifkan terlebih dahulu.
    Meskipun demikian, praktik terbaik (best practice) adalah tetap mengaktifkan CloudTrail dan VPC Flow Logs untuk analisis Anda.

4. Menyesuaikan Pengaturan Detector (Customizing Detector Settings)
Anda dapat menyesuaikan perilaku GuardDuty sesuai kebutuhan keamanan spesifik organisasi.
a. Adjusting Threat Intelligence Feeds
    GuardDuty terintegrasi dengan umpan threat intelligence eksternal.
    Sesuaikan umpan mana yang ingin digunakan berdasarkan profil ancaman organisasi.

b. Setting Finding Thresholds
    Konfigurasi ambang batas temuan (finding thresholds) untuk menyesuaikan sensitivitas GuardDuty.
    Sesuaikan pengaturan ini untuk menerima temuan berdasarkan tingkat kepercayaan yang diinginkan terhadap ancaman yang terdeteksi.

c. Notification and Alert Settings
    Tentukan bucket S3 dan topik SNS untuk menyimpan temuan dan menerima notifikasi.
    Konfigurasi pengaturan ini untuk memastikan tim keamanan segera mendapat peringatan ketika GuardDuty mendeteksi aktivitas mencurigakan.

d. User Permission Settings
    Definisikan peran IAM dan izin (permissions) untuk pengguna GuardDuty.
    Pastikan anggota tim yang sesuai memiliki akses yang diperlukan untuk melihat temuan dan merespons insiden.

e. Automated Responses
    Eksplorasi opsi respons otomatis, seperti mengintegrasikan temuan GuardDuty dengan AWS Lambda functions.
    Memungkinkan otomatisasi respons terhadap jenis ancaman keamanan tertentu, meningkatkan kemampuan incident response.
