Group and Role Management - 2

What is an AWS IAM Role?
In AWS IAM, a role is a set of permissions that define what actions an entity (such as an AWS service, user, or application) can perform within your AWS environment. Think of an IAM role as a set of policies that specify what actions are allowed or denied for its assigned entities. Roles are not associated directly with users but are assumed by users, applications, or AWS services to temporarily gain permissions and carry out specific tasks, or access resources.

Roles are used to delegate access across different AWS accounts, services, or resources securely. They help manage permissions effectively by following the principle of least privilege, granting only the necessary permissions required for a specific task or service.

For example, you can create an IAM role that allows an AWS Lambda function to access an S3 bucket, or you can create a role that permits an EC2 instance to manage resources within an AWS account.

Roles facilitate secure access management and enable various entities within AWS to perform tasks or access resources without the need to share long-term credentials, enhancing security and reducing potential risks associated with excessive access or credential exposure.

Common Scenarios
Cross-Account Access

Use Case : An organization ("Account A") has separate AWS accounts for development and production purposes. The development team, operating in the development account, requires access to specific resources (e.g., S3 buckets) within the production account for testing purposes. However, direct access with long-term credentials is not preferred due to security concerns.

Solution with IAM Roles:

1. Setup in Production Account (Account B)
In the production account, create an IAM role (e.g., "DevTeamRole") with permissions allowing read-only access to the required S3 buckets.
Define a trust policy for this role that specifies the development account (Account A) as a trusted entity, allowing roles from Account A to assume this role.

2. Assuming the Role from Development Account (Account A)
In the development account, configure IAM roles for the development team users.
Define policies granting the necessary permissions to assume the "DevTeamRole" in the production account.
When users from the development team need access to the production resources, they assume the "DevTeamRole" in the production account through the IAM console, CLI, or SDK.

3. Accessing Production Resources
Once assumed, users temporarily obtain credentials associated with the "DevTeamRole" in the production account.
They can now access the specified S3 buckets or other permitted resources in the production account based on the defined permissions of the assumed role.

Application Services Access
Use Case : A serverless application running on AWS Lambda needs to access an S3 bucket to process and store data. However, providing long-term access keys within the application for accessing the S3 bucket poses security risks.

Solution with IAM Roles:
1. Creating an IAM Role
    Go to the IAM console in your AWS Management Console.
    Select "Roles" and then click on "Create role."
    Choose the service that will use this role (AWS Lambda).
    Click on “Next”.
![1](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/5.Group+and+Role+Management-2/image5_1.png)

Select the AWS-managed policies “ AWSLambdaBasicExecutionRole ” and “ AWSXRayDaemonWriteAccess ”, and click on “Next”.
![2](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/5.Group+and+Role+Management-2/image5_2.png)

Enter a Role name and then choose “Create role.”
![3](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/5.Group+and+Role+Management-2/image5_3.png)

2. From the list of IAM roles, choose the role that you just created.
![4](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/5.Group+and+Role+Management-2/image5_4.png)

The trust policy needs to enable Lambda to assume the execution role by including “lambda.amazonaws.com” as a trusted service. To achieve this, access the “Trust Relationships” tab, select “Edit trust policy”, and update the policy with the following content:
{
  "Version": "2012-10-17",
  "Statement": [
    {
     "Effect": "Allow",
     "Principal": {
     "Service": "lambda.amazonaws.com"
    },
  "Action": "sts:AssumeRole"
  }
 ]
}

If the trust policy is correct you can skip this part.
![5](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/5.Group+and+Role+Management-2/image5_5.png)

Choose “Update policy.”

3. In the Permissions tab, select “Create inline policy.”
![6](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/5.Group+and+Role+Management-2/image5_6.png)

4. Choose the JSON tab.
![7](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/5.Group+and+Role+Management-2/image5_7.png)

5. Enter a resource-based IAM policy that grants access to your S3 bucket.
This IAM policy offers access to a particular Amazon S3 bucket specifically for obtaining permissions using the Get action. When accessing objects within the bucket, ensure accurate path specification or utilize a wildcard character ("*").                    
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ExampleStmt",
      "Action": [
        "s3:GetObject"
      ],
      "Effect": "Allow",
      "Resource": [
        "arn:aws:s3:::/*"
      ]
    }
  ]
}
               
Replace "arn:aws:s3:::<bucket_name>" with your S3 buckets Amazon Resource Name (ARN).

6. Choose Next.
    Enter a name for your policy.
    Select “Create policy.”
![8](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/5.Group+and+Role+Management-2/image5_8.png)

7. Set up the IAM role as the execution role for your Lambda functions.
    Access the Lambda console.
    Select your Lambda function.
    Under "Execution role," choose the existing IAM role you created.
    Save your changes.

8. Verify the S3 bucket policy.
The following example IAM S3 bucket policy grants a Lambda execution role access to an S3 bucket.
{
  "Id": "ExamplePolicy",
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ExampleStmt",
      "Action": [
        "s3:GetObject"
      ],
      "Effect": "Allow",
      "Resource": [
        "arn:aws:s3:::/*"
      ],
      "Principal": {
        "AWS": [
          "arn:aws:iam:::role/Lambda_allow_S3"
        ]
      }
    }
  ]
}

After completing these steps, your Lambda function will have the necessary permissions to access the specified Amazon S3 bucket. You can then write code within your Lambda function to interact with the S3 bucket using AWS SDKs or Lambda runtime environments. 

1. Apa Itu AWS IAM Role?
    Role adalah sekumpulan izin (set of permissions) yang mendefinisikan tindakan apa yang dapat dilakukan oleh suatu entitas (seperti AWS service, user, atau aplikasi) di dalam lingkungan AWS.
    Role tidak terkait langsung dengan pengguna, tetapi di-asumsikan (assumed) oleh pengguna, aplikasi, atau layanan AWS untuk sementara waktu guna mendapatkan izin dan melakukan tugas tertentu atau mengakses sumber daya.
    Role digunakan untuk mendelegasikan akses secara aman antar akun AWS, layanan, atau sumber daya yang berbeda.
    Role mengikuti prinsip least privilege, hanya memberikan izin yang diperlukan untuk tugas atau layanan tertentu.

Contoh penggunaan role:
    Role yang memungkinkan AWS Lambda function mengakses S3 bucket.
    Role yang mengizinkan EC2 instance mengelola sumber daya di dalam akun AWS.

Keuntungan:
    Memungkinkan berbagai entitas di AWS melakukan tugas atau mengakses sumber daya tanpa perlu berbagi long-term credentials (kredensial jangka panjang).
    Meningkatkan keamanan dan mengurangi potensi risiko yang terkait dengan akses berlebihan atau paparan kredensial.

2. Common ScenarioS
A. Cross-Account Access
Use Case:
    Organisasi ("Account A") memiliki akun AWS terpisah untuk keperluan development dan production.
    Tim development (di akun development) memerlukan akses ke sumber daya tertentu (misalnya S3 buckets) di dalam akun production untuk tujuan pengujian.
    Akses langsung dengan long-term credentials tidak diinginkan karena alasan keamanan.

Solution dengan IAM Roles:

Step 1 – Setup di Production Account (Account B)
    Buat IAM role (misal: "DevTeamRole") dengan izin yang mengizinkan read-only access ke S3 buckets yang diperlukan.
    Definisikan trust policy untuk role ini yang menyebutkan development account (Account A) sebagai trusted entity, sehingga role dari Account A dapat mengasumsikan role ini.

Step 2 – Assuming the Role dari Development Account (Account A)
    Di akun development, konfigurasi IAM roles untuk tim development.
    Definisikan policies yang memberikan izin yang diperlukan untuk mengasumsikan "DevTeamRole" di akun production.
    Ketika pengguna dari tim development memerlukan akses ke sumber daya production, mereka mengasumsikan "DevTeamRole" di akun production melalui IAM console, CLI, atau SDK.

Step 3 – Accessing Production Resources
    Setelah diasumsikan, pengguna sementara mendapatkan credentials yang terkait dengan "DevTeamRole" di akun production.
    Mereka sekarang dapat mengakses S3 buckets atau sumber daya lain yang diizinkan di akun production berdasarkan izin dari role yang diasumsikan.

B. Application Services Access

Use Case:
    Aplikasi serverless yang berjalan di AWS Lambda perlu mengakses S3 bucket untuk memproses dan menyimpan data.
    Menyediakan long-term access keys di dalam aplikasi untuk mengakses S3 bucket menimbulkan risiko keamanan.

Solution dengan IAM Roles:

Step 1 – Creating an IAM Role
    Buka IAM console, pilih "Roles", lalu klik "Create role".
    Pilih layanan yang akan menggunakan role ini (AWS Lambda).
    Pilih managed policies: AWSLambdaBasicExecutionRole dan AWSXRayDaemonWriteAccess.
    Masukkan Role name dan klik "Create role".

Step 2 – Trust Policy
    Dari daftar IAM roles, pilih role yang baru dibuat.
    Akses tab "Trust Relationships", pilih "Edit trust policy", dan update policy dengan konten yang mengizinkan lambda.amazonaws.com sebagai trusted service.

Step 3 – Create Inline Policy untuk S3 Access
    Di tab Permissions, pilih "Create inline policy".
    Pilih tab JSON, masukkan resource-based IAM policy yang memberikan akses ke S3 bucket (contoh: s3:GetObject).
    Ganti ARN bucket dengan ARN S3 bucket yang sesuai.
    Beri nama policy dan klik "Create policy".

Step 4 – Set up IAM Role sebagai Execution Role untuk Lambda
    Akses Lambda console, pilih Lambda function Anda.
    Di bawah "Execution role", pilih existing IAM role yang telah dibuat.
    Simpan perubahan.

Step 5 – Verify S3 Bucket Policy
    Contoh IAM S3 bucket policy yang memberikan akses ke Lambda execution role untuk mengakses S3 bucket (dengan Principal mencakup ARN role Lambda).

Hasil Akhir:
    Setelah langkah-langkah ini selesai, Lambda function Anda akan memiliki izin yang diperlukan untuk mengakses S3 bucket yang ditentukan.
    Anda kemudian dapat menulis kode di dalam Lambda function untuk berinteraksi dengan S3 bucket menggunakan AWS SDKs atau Lambda runtime environments.
