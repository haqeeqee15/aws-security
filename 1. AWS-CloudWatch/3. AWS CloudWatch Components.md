AWS CloudWatch Components

AWS CloudWatch is comprised of several essential components that work together to provide comprehensive monitoring and observability capabilities for your AWS environment. Understanding these components is crucial for effectively using CloudWatch. Here are the core components:


Metrics:
- Metrics are the foundation of AWS CloudWatch. They are essentially data points that represent the performance of various AWS resources and services. Metrics can be thought of as time-series data that capture the behavior and state of AWS resources over time.
- AWS provides a wide range of pre-defined metrics for its services, such as CPU utilization for EC2 instances or request count for an S3 bucket. You can also create custom metrics to monitor specific aspects of your applications or resources.
- Metrics can be collected at regular intervals, and CloudWatch retains this data for a specified retention period, allowing you to analyze historical trends.

Alarms:
- Alarms in CloudWatch are used to monitor metrics and trigger automated actions when certain conditions are met or thresholds are crossed. They are a proactive way to respond to issues and take corrective action.
- For example, you can set up an alarm to notify you when the CPU utilization of an EC2 instance exceeds a specified threshold. Alarms can trigger actions like sending notifications via Amazon SNS, stopping or terminating instances, or invoking AWS Lambda functions.
- Alarms can help you maintain the desired operational state of your AWS resources and applications.

Dashboards:
- CloudWatch Dashboards provide a customizable and visual way to monitor the health and performance of your AWS environment. You can create and arrange widgets on a dashboard to display metrics, logs, and alarms that are most relevant to your monitoring needs.
- Dashboards allow you to create a centralized view of your AWS resources, making it easy to track and analyze metrics in real-time. They are especially useful for teams that need a high-level overview of their infrastructure.

Logs:
- CloudWatch Logs allow you to collect, store, and analyze log data from your applications, services, and AWS resources. Logs provide valuable insights into what is happening within your environment.
- You can configure log groups to organize log streams, which are individual sources of log data. For example, you might have log streams for different parts of your application.
- Log data can be searched, filtered, and analyzed using CloudWatch Logs Insights or integrated with other AWS services like Amazon Elasticsearch or AWS Lambda for advanced analytics and processing.



Events and EventBridge
- CloudWatch Events (formerly CloudWatch Events) and EventBridge allow you to respond to events and changes in your AWS environment in real-time. Events can be generated by AWS services, custom applications, or third-party sources.
- You can create rules to match specific events and define targets to trigger actions, such as invoking AWS Lambda functions, starting AWS Step Functions, or sending events to Amazon SNS topics.
- Events and EventBridge enable event-driven architectures and are essential for automating responses to changes in your AWS environment.

Synthetic Monitoring (Canary)
- AWS CloudWatch Synthetics allows you to set up canaries, which are configurable scripts that simulate user interactions with your applications. Canaries monitor the availability and performance of your applications and provide data for creating custom metrics and alarms.

Understanding how these components work together is key to implementing effective monitoring and observability in your AWS environment. In the subsequent sections of this training, we will dive deeper into each of these components, explaining how to create and configure them to meet your specific monitoring needs.

Let's proceed with exploring each of these components in more detail and learn how to leverage them for better AWS resource management and application performance monitoring.

Metrics in AWS CloudWatch
Metrics are the fundamental building blocks of AWS CloudWatch. They are numerical data points that provide insight into the performance and behavior of your AWS resources and services. Metrics are collected over time, allowing you to monitor, analyze, and respond to changes in your AWS environment.

How Metrics Are Collected
- Data Collection: Metrics are collected at regular intervals, typically every minute, and sent to CloudWatch. AWS services and resources automatically send predefined metrics to CloudWatch.
- Custom Metrics: To monitor specific aspects of your applications or resources, you can create custom metrics. This involves using the CloudWatch API or AWS SDKs to publish metric data. Custom metrics are essential for tracking application-specific performance indicators or business KPIs.

Demonstrating Custom Metric Creation
1. Install AWS SDK: If you want to create custom metrics, first ensure that you have the AWS SDK or CLI installed, which allows you to interact with CloudWatch programmatically.
2. Publish Custom Metrics: Use the SDK or CLI to publish custom metric data to CloudWatch. You'll need to specify the metric's name, namespace, and dimensions (if applicable).
3. Set Up Metric Filters: To enable CloudWatch to process and analyze log data, set up metric filters within CloudWatch Logs. Metric filters extract data and convert it into custom metrics.
4. Create a Custom Dashboard: Once you have your custom metrics, create a custom dashboard to visualize and monitor these metrics. Dashboards allow you to create custom views of your data.


Custom metrics give you the flexibility to monitor and respond to specific aspects of your AWS resources and applications that are unique to your use case.

CloudWatch Alarms
CloudWatch Alarms are a powerful feature that allows you to monitor metrics and take automated actions when specific conditions or thresholds are met. Alarms are a proactive way to manage your AWS resources and applications.

Concept of CloudWatch Alarms
- Thresholds: Alarms are set based on metric thresholds. You define a threshold value, and when the metric crosses that value (e.g., CPU utilization exceeding 90% for five minutes), the alarm triggers.
- Actions: When an alarm is triggered, you can configure actions to take. These actions can include sending notifications via Amazon SNS, stopping or terminating EC2 instances, invoking AWS Lambda functions, or running Auto Scaling policies.

Creating and Configuring Alarms
1. Select a Metric: Choose the metric you want to monitor with an alarm. This could be a predefined AWS metric or a custom metric you've created.
2. Define the Threshold: Set the threshold value for the metric that will trigger the alarm.
3. Specify Actions: Define the actions to be taken when the alarm is triggered. You can set up notification actions to alert your team or automate responses.
4. Set Up Additional Alarm Configuration: Configure optional settings, such as the alarm's name, description, and evaluation period.
5. Create the Alarm: Once you've configured the alarm, create it. The alarm will start monitoring the metric immediately.

CloudWatch Alarms ensure that you're proactively alerted to issues and can respond swiftly to maintain the health and performance of your AWS environment.

CloudWatch Dashboards
CloudWatch Dashboards provide a visual way to monitor and customize the presentation of your metrics. Dashboards allow you to create customized views that display the most important data for your monitoring needs.

Purpose of CloudWatch Dashboards
- Customization: Dashboards enable you to create tailored views of your AWS environment. You can arrange widgets to display specific metrics, alarms, or logs that are relevant to your use case.
- Real-Time Monitoring: Dashboards provide real-time visualizations, allowing you to track the health and performance of your AWS resources at a glance.

Creating Custom Dashboards
1. Access the CloudWatch Console: Log in to the AWS Management Console and navigate to CloudWatch.
2. Create a New Dashboard: In the CloudWatch console, select "Dashboards" and then click "Create Dashboard."
3. Add Widgets: Customize your dashboard by adding widgets. Widgets can display metrics, alarms, or text/Markdown for documentation.
4. Configure Widgets: Each widget can be configured to display specific metrics or logs. You can adjust the time range and customize the widget's appearance.
5. Save the Dashboard: Give your dashboard a name and save it. You can also share dashboards with other AWS accounts or make them public.

CloudWatch Dashboards provide a centralized and visual way to monitor the health and performance of your AWS environment, making it easier to identify and respond to issues.

CloudWatch Logs
CloudWatch Logs allows you to collect, store, and analyze log data from your applications, services, and AWS resources. It plays a crucial role in troubleshooting and gaining insights into your system's behavior.
How CloudWatch Logs Work
- Log Groups: Log data is organized into "log groups," which represent a logical grouping of related log streams. For example, you might have a log group for your application's access logs.
- Log Streams: Log streams within a log group are individual sources of log data. Each log stream can represent a different source or instance, such as an EC2 instance or Lambda function.

Setting Up Log Groups and Log Streams
1. Create a Log Group: In the CloudWatch console, navigate to "Log groups" and create a new log group. Give it a name that reflects the type of logs you'll be collecting.
2. Configure Log Streams: Within a log group, you can configure log streams. Log streams are typically automatically created as new log data is ingested. However, you can also create custom log streams if needed.
3. Publish Log Data: Use the CloudWatch Logs SDK or AWS CLI to publish log data to the appropriate log stream. Your applications and AWS resources can send log data to CloudWatch Logs.


Log Retention Policies
- CloudWatch Logs allows you to define retention policies for log data. This determines how long log data is retained. You can specify retention periods ranging from a few days to indefinitely.

Log data is a valuable source of information for troubleshooting, security analysis, and compliance. By centralizing logs in CloudWatch, you can easily access and analyze this data.


Events and EventBridge in CloudWatch
CloudWatch Events and EventBridge are event-driven monitoring and automation tools that allow you to respond to changes and events within your AWS environment in real-time.

Introducing CloudWatch Events and EventBridge
- Events: Events are generated by AWS services, custom applications, or third-party sources. These events can signify changes in your AWS environment, such as instance launches, S3 bucket object creations, or CloudTrail log events.
- Event Rules: CloudWatch Events uses "rules" to match specific events based on their attributes. You can define rules to capture events that are relevant to your use case.
- Targets: When an event matches a rule, you can specify "targets" to define what action should be taken. Targets can include AWS Lambda.

Komponen Inti AWS CloudWatch

CloudWatch terdiri dari beberapa komponen yang bekerja bersama untuk menyediakan monitoring dan observability.

2. Metrics
A. Definisi Metrics
    Metrics adalah fondasi CloudWatch.
    Berupa data numerik (time-series) yang merepresentasikan performa sumber daya AWS dari waktu ke waktu.

B. Jenis Metrics
    Pre-defined metrics: disediakan AWS untuk berbagai layanan (contoh: CPU utilization untuk EC2, request count untuk S3 bucket).
    Custom metrics: dibuat sendiri untuk memantau aspek spesifik dari aplikasi atau sumber daya.

C. Karakteristik
    Dikumpulkan secara berkala.
    Data disimpan untuk periode retensi tertentu, memungkinkan analisis tren historis.

3. Alarms
A. Definisi Alarms
    Digunakan untuk memantau metrics dan memicu tindakan otomatis saat kondisi tertentu terpenuhi atau ambang batas dilampaui.
    Bersifat proaktif untuk merespons masalah.

B. Cara Kerja
    Tentukan threshold (contoh: CPU utilization > 90% selama 5 menit).
    Tentukan actions yang akan dipicu (notifikasi via SNS, stop/terminate EC2, invoke Lambda, atau Auto Scaling policies).

C. Contoh Penggunaan
    Alarm memberi notifikasi saat CPU utilization melebihi batas tertentu.
    Membantu mempertahankan kondisi operasional yang diinginkan.

4. Dashboards
A. Definisi Dashboards
    Tampilan visual yang dapat disesuaikan (customizable) untuk memantau kesehatan dan performa lingkungan AWS.

B. Manfaat
    Membuat tampilan terpusat dari sumber daya AWS.
    Memantau metrik secara real-time.
    Sangat berguna untuk tim yang membutuhkan gambaran tingkat tinggi (high-level overview) dari infrastruktur.

C. Cara Membuat
    Akses CloudWatch Console.
    Pilih "Dashboards" → "Create Dashboard".
    Tambahkan widget (menampilkan metrik, alarm, atau teks/Markdown).
    Konfigurasi setiap widget (metrik, logs, rentang waktu, tampilan).
    Simpan dan beri nama dashboard. Dapat dibagikan ke akun AWS lain atau dibuat publik.

5. Logs
A. Definisi Logs
    Mengumpulkan, menyimpan, dan menganalisis data log dari aplikasi, layanan, dan sumber daya AWS.
    Memberikan wawasan tentang apa yang terjadi di dalam lingkungan AWS.

B. Organisasi Log
    Log groups: pengelompokan logis dari log streams yang terkait (contoh: group untuk access logs aplikasi).
    Log streams: sumber individu dari data log (contoh: stream untuk setiap EC2 instance atau Lambda function).

C. Kemampuan
    Data log dapat dicari, difilter, dan dianalisis menggunakan CloudWatch Logs Insights.
    Dapat diintegrasikan dengan layanan AWS lain (Amazon Elasticsearch, Lambda) untuk analisis lanjutan.

D. Retention Policies
    Menentukan berapa lama data log disimpan (dari beberapa hari hingga tidak terbatas).

6. Events dan EventBridge
A. Definisi
    CloudWatch Events dan EventBridge adalah alat monitoring dan otomatisasi berbasis event (event-driven).
    Memungkinkan respons secara real-time terhadap perubahan dan event di lingkungan AWS.

B. Komponen
    Events: dihasilkan oleh layanan AWS, aplikasi kustom, atau sumber pihak ketiga (contoh: instance launch, S3 object creation, CloudTrail log events).
    Event Rules: aturan untuk mencocokkan event spesifik berdasarkan atributnya.
    Targets: tindakan yang diambil saat event cocok dengan rule (contoh: invoke Lambda, start Step Functions, kirim ke SNS topic).

C. Manfaat
    Mendukung arsitektur event-driven.
    Esensial untuk mengotomatisasi respons terhadap perubahan di lingkungan AWS.

7. Synthetic Monitoring (Canary)
A. Definisi
    AWS CloudWatch Synthetics memungkinkan pembuatan canaries.
    Canaries adalah skrip yang dapat dikonfigurasi untuk mensimulasikan interaksi pengguna dengan aplikasi.

B. Fungsi
    Memantau ketersediaan (availability) dan performa aplikasi.
    Menyediakan data untuk membuat custom metrics dan alarms.
