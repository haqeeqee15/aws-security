AWS Incident Manager

Impactful incidents can disrupt and degrade the performance of applications hosted on AWS. “AWS Incident Manager”, a vital feature of AWS Systems Manager, is specifically designed to assist in mitigating and recovering from such incidents.

In the AWS context, an incident refers to any unexpected disruption or deterioration in service quality that could have a significant impact on business operations. Therefore, it is crucial for organizations to develop a response strategy to efficiently manage and recover from incidents promptly, while also implementing measures to prevent future occurrences.

Incident Manager helps to decrease the time it takes to solve incidents by:
    Providing automated plans to effectively involve the people responsible for handling incidents.
    Giving relevant troubleshooting information.
    Allowing automated response actions through predefined Automation runbooks.
    Offering ways to work together and communicate with all parties involved.


The features and processes included in Incident Manager are based on the best practices for incident response that Amazon has been improving since it started. Additionally, Incident Manager smoothly connects with important AWS services like Amazon CloudWatch, AWS CloudTrail, AWS Systems Manager, and Amazon EventBridge.

Key Components and Features

This segment outlines the primary components and features within Incident Manager that facilitate the establishment of comprehensive incident response plans.
Response Plan
    Functions as a model that shows important parts during an incident.
    Contains information like who should respond, the automatic response to reduce the incident, and the chosen tool for communication and automatic notifications.

Incident Detection
    Customizable Amazon CloudWatch alarms and Amazon EventBridge events make problems when things go wrong with AWS resources.

Runbook Automation Support
    Start Automation Runbooks in Incident Manager for automatic replies, providing clear steps to the first responders.

Engagement and Escalation
    Engagement plans show who to tell when something happens and make sure important people know about it and get involved.


On-call Schedules
    Involves taking turns with as many as 30 people to make sure there is always someone available.
    Used in plans for when things get more serious to decide who gets contacted when there's a problem that needs immediate attention.


Active Collaboration
    The people who respond to incidents use AWS Chatbot to communicate in chat channels like Slack, Microsoft Teams, or Amazon Chime. This allows them to talk directly, get automatic notifications, and in Slack and Microsoft Teams, carry out certain Incident Manager CLI operations.


Incident Diagnosis
    In the Incident Manager, people who respond to problems can see the latest information while things are happening. When the information changes, they make new tasks and fix things using Automation runbooks.


Post-Incident Analysis
    After an incident is resolved, a review is done to find ways to improve how incidents are handled, such as how quickly they are detected and resolved.
    This review helps to figure out the main reasons for the incidents, and the Incident Manager suggests things to do to make incident response better.

Benefits of Using Incident Manager
Learn about how Incident Manager can help with detecting and responding to incidents. This part shows the good things that happen in a company when they use an Incident Manager response plan.

Incident Manager is a tool that automatically creates incidents based on Amazon CloudWatch alarms and EventBridge events in response to unplanned interruptions or reductions in service quality. CloudWatch alarms detect changes to metrics, while EventBridge events result from specified changes in an environment, application, or service. Actions for incident creation and the appropriate response plan can be specified during alarm or event configuration.

Incident Manager enables the automatic collection and tracking of incident-related metrics through CloudWatch metrics. In addition to the metrics generated by CloudWatch alarms at incident creation, real-time manual addition of metrics provides extra context and data for responders.

The Incident Manager incident timeline is used to chronologically display points of interest. Responders can contribute to the timeline by adding custom events describing their actions. Automated points of interest include incident creation, metric reporting, responder engagement, and successful completion of runbook steps.

Incident Manager brings together incident responders through contacts, on-call schedules, escalation plans, and chat channels. Individual contacts, along with their preferences (email, SMS, or voice), are defined directly in Incident Manager. On-call schedule rotations, which include added contacts, determine responder engagement during specific periods. Defined contacts and on-call schedules contribute to the creation of escalation plans, ensuring the engagement of necessary responders at the right time during an incident.

Utilizing an AWS Chatbot client configured for Slack, Microsoft Teams, or Amazon Chime, responders can collaborate in their preferred chat channels, interacting directly with the incident and each other. Incident Manager displays real-time actions of incident responders in the chat channel, providing context to all involved.

Incident Manager's Automation runbooks enable responders to focus on critical tasks for incident resolution. These runbooks, predefined series of actions, combine automated and manual steps as needed, allowing responders to concentrate on analyzing and responding to impact.

Post-incident analysis in Incident Manager supports iterative learning and improvement of runbooks, response plans, and metrics, helping to prevent future incidents and downtime. It enables the development of more robust response plans and the implementation of changes across applications, thus preventing future incidents.

AWS Incident Manager Use Cases

Security Incidents
Situation : When a security breach occurs in an AWS environment, potentially exposing sensitive data, Incident Manager can automatically trigger response plans. It notifies security teams via SMS and phone calls, executes runbooks from AWS Systems Manager to isolate affected resources, and initiates investigation processes. This swift and automated response helps contain the security incident and minimizes the impact on data integrity.

Operational Incidents
Situation : If there's an unexpected surge in traffic causing performance degradation in an application, AWS Incident Manager can respond to CloudWatch alarms triggered by performance metrics. It engages the operations team through designated chat channels using AWS Chatbot, and runbooks are executed to scale resources horizontally. This ensures a prompt response to operational issues, reducing downtime and maintaining a positive user experience.

Compliance-Related Incidents
Situation : In cases where an AWS environment must adhere to specific compliance standards and an audit identifies configuration drift, Incident Manager can automatically respond to compliance-related alarms. It notifies the compliance team through integrated communication channels and executes runbooks to remediate the configuration drift, ensuring compliance is maintained. This proactive approach to compliance incidents helps organizations avoid penalties and maintain a secure posture.

Infrastructure Failures
Situation : When critical infrastructure components experience failures, impacting the overall availability of services, Incident Manager can respond to AWS Health events or CloudWatch alarms indicating infrastructure issues. It engages the appropriate teams via SMS and phone calls, initiates runbooks to diagnose and resolve the failures, and provides real-time updates through designated chat channels. This rapid and automated response minimizes downtime and accelerates the recovery of affected services.

Collaborative Incident Response
Situation : Incidents that require collaboration among multiple teams, including development, operations, and security, are effectively managed with Incident Manager. It serves as a centralized hub for collaboration, integrating with AWS Chatbot to notify teams and providing a unified interface for incident tracking through OpsCenter. This collaborative approach ensures that all stakeholders have real-time visibility into incident details, facilitating coordinated efforts and faster resolution.

Post-Incident Analysis and Improvement
Situation : After resolving an incident, organizations aim to analyze the root cause and implement improvements. Incident Manager suggests post-incident actions, such as automating specific runbook steps or adding new alarms based on best practices. This continuous improvement cycle enhances the overall incident response process, making it more resilient and adaptive to evolving challenges.

In each of these scenarios, AWS Incident Manager demonstrates its versatility and effectiveness in automating responses, improving collaboration, and facilitating a structured approach to incident resolution in AWS environments. The service's ability to integrate with various AWS components ensures a comprehensive and cohesive incident response strategy. 

1. Definisi AWS Incident Manager
    Merupakan fitur penting (vital feature) dari AWS Systems Manager.
    Dirancang khusus untuk membantu mitigasi dan pemulihan dari insiden yang dapat mengganggu dan menurunkan kinerja aplikasi yang dihosting di AWS.

2. Definisi Insiden dalam Konteks AWS
    Insiden adalah gangguan tak terduga (unexpected disruption) atau penurunan kualitas layanan (deterioration in service quality) yang dapat berdampak signifikan pada operasi bisnis.

3. Tujuan Incident Manager
Membantu mengurangi waktu yang dibutuhkan untuk menyelesaikan insiden dengan cara:
    Menyediakan rencana otomatis untuk melibatkan orang yang bertanggung jawab menangani insiden.
    Memberikan informasi troubleshooting yang relevan.
    Memungkinkan tindakan respons otomatis melalui predefined Automation runbooks.
    Menawarkan cara untuk bekerja sama dan berkomunikasi dengan semua pihak yang terlibat.

4. Fondasi dan Integrasi
    Fitur dan proses di Incident Manager didasarkan pada best practices untuk respons insiden yang telah disempurnakan oleh Amazon sejak awal.
    Terintegrasi secara mulus dengan layanan AWS penting: Amazon CloudWatch, AWS CloudTrail, AWS Systems Manager, dan Amazon EventBridge.

5. Komponen dan Fitur Utama
a. Response Plan
    Berfungsi sebagai model yang menunjukkan bagian penting selama insiden.
    Berisi informasi: siapa yang harus merespons, respons otomatis untuk mengurangi insiden, alat komunikasi yang dipilih, dan notifikasi otomatis.

b. Incident Detection
    CloudWatch alarms dan EventBridge events yang dapat disesuaikan (customizable) mendeteksi masalah pada sumber daya AWS.

c. Runbook Automation Support
    Menjalankan Automation Runbooks di Incident Manager untuk respons otomatis, memberikan langkah-langkah jelas kepada first responders.

d. Engagement and Escalation
    Engagement plans: menunjukkan siapa yang harus diberi tahu saat insiden terjadi.
    Memastikan orang-orang penting mengetahui dan terlibat.

e. On-call Schedules
    Melibatkan giliran hingga 30 orang untuk memastikan selalu ada yang tersedia.
    Digunakan dalam rencana eskalasi untuk menentukan siapa yang dihubungi saat masalah membutuhkan perhatian segera.

f. Active Collaboration
    Responder menggunakan AWS Chatbot untuk berkomunikasi di saluran chat (Slack, Microsoft Teams, atau Amazon Chime).
    Memungkinkan komunikasi langsung, notifikasi otomatis, dan operasi CLI Incident Manager tertentu (di Slack dan Teams).

g. Incident Diagnosis
    Responder dapat melihat informasi terbaru secara real-time.
    Saat informasi berubah, mereka membuat tugas baru dan memperbaiki menggunakan Automation runbooks.

h. Post-Incident Analysis
    Setelah insiden diselesaikan, dilakukan review untuk menemukan cara meningkatkan penanganan insiden (kecepatan deteksi dan resolusi).
    Membantu menentukan akar penyebab utama insiden. Incident Manager menyarankan tindakan untuk meningkatkan respons insiden di masa depan.

6. Manfaat Menggunakan Incident Manager
a. Deteksi dan Pembuatan Insiden Otomatis
    Secara otomatis membuat insiden berdasarkan CloudWatch alarms dan EventBridge events.
    Tindakan untuk pembuatan insiden dan response plan yang sesuai dapat ditentukan selama konfigurasi alarm atau event.

b. Pengumpulan dan Pelacakan Metrik Otomatis
    Mengumpulkan dan melacak metrik terkait insiden melalui CloudWatch metrics.
    Penambahan metrik secara manual real-time memberikan konteks tambahan bagi responder.

c. Incident Timeline
    Menampilkan poin-poin penting secara kronologis.
    Responder dapat berkontribusi dengan menambahkan event kustom. Poin otomatis: pembuatan insiden, pelaporan metrik, engagement responder, dan penyelesaian langkah runbook.

d. Menyatukan Responder
    Melalui kontak, on-call schedules, escalation plans, dan saluran chat.
    Kontak individu (dengan preferensi email, SMS, atau voice) didefinisikan langsung di Incident Manager.
    Rotasi on-call schedule menentukan engagement responder selama periode tertentu.

e. Kolaborasi di Saluran Chat
    Responder dapat berkolaborasi di saluran chat pilihan (Slack, Teams, Chime).
    Incident Manager menampilkan tindakan real-time responder di saluran chat.

f. Fokus pada Tugas Kritis dengan Automation Runbooks
    Runbook (serangkaian tindakan yang telah ditentukan) menggabungkan langkah otomatis dan manual.
    Memungkinkan responder fokus pada analisis dan respons terhadap dampak.

g. Post-Incident Analysis untuk Perbaikan Berkelanjutan
    Mendukung pembelajaran iteratif dan peningkatan runbook, response plans, dan metrik.
    Membantu mencegah insiden dan downtime di masa depan.

7. Use Cases AWS Incident Manager
a. Security Incidents
    Situasi: Pelanggaran keamanan di lingkungan AWS yang berpotensi mengekspos data sensitif.
    Tindakan: Memicu response plans secara otomatis, memberi notifikasi tim keamanan via SMS/telepon, menjalankan runbook untuk mengisolasi sumber daya yang terdampak, memulai proses investigasi.

b. Operational Incidents
    Situasi: Lonjakan lalu lintas tak terduga menyebabkan degradasi performa aplikasi.
    Tindakan: Merespons CloudWatch alarms yang dipicu metrik performa, melibatkan tim operasi melalui saluran chat, menjalankan runbook untuk menskalakan sumber daya secara horizontal.

c. Compliance-Related Incidents
    Situasi: Lingkungan AWS harus mematuhi standar kepatuhan tertentu dan audit mengidentifikasi configuration drift.
    Tindakan: Merespons alarm kepatuhan secara otomatis, memberi notifikasi tim kepatuhan melalui saluran chat terintegrasi, menjalankan runbook untuk memperbaiki configuration drift.

d. Infrastructure Failures
    Situasi: Komponen infrastruktur kritis mengalami kegagalan, berdampak pada ketersediaan layanan.
    Tindakan: Merespons AWS Health events atau CloudWatch alarms, melibatkan tim yang tepat via SMS/telepon, memulai runbook untuk mendiagnosis dan menyelesaikan kegagalan, memberikan update real-time melalui saluran chat.

e. Collaborative Incident Response
    Situasi: Insiden yang memerlukan kolaborasi antar beberapa tim (development, operations, security).
    Tindakan: Berfungsi sebagai hub terpusat untuk kolaborasi, terintegrasi dengan AWS Chatbot untuk notifikasi tim, menyediakan antarmuka terpadu untuk pelacakan insiden melalui OpsCenter.

f. Post-Incident Analysis and Improvement
    Situasi: Setelah insiden diselesaikan, organisasi ingin menganalisis akar penyebab dan menerapkan perbaikan.
    Tindakan: Incident Manager menyarankan tindakan pasca-insiden (mengotomatiskan langkah runbook tertentu atau menambahkan alarm baru berdasarkan best practices). Siklus peningkatan berkelanjutan.

8. Kesimpulan
    AWS Incident Manager menunjukkan fleksibilitas dan efektivitas dalam mengotomatiskan respons, meningkatkan kolaborasi, dan memfasilitasi pendekatan terstruktur untuk resolusi insiden di lingkungan AWS.
    Kemampuan layanan ini untuk berintegrasi dengan berbagai komponen AWS memastikan strategi respons insiden yang komprehensif dan kohesif.
