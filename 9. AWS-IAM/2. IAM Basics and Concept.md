IAM Basics and Concepts

What is IAM?
AWS IAM (Identity and Access Management) is a service provided by Amazon Web Services (AWS) that enables you to securely manage access to various AWS services and resources. It allows you to control access to particular resources and define the actions that users can take within your AWS environment.

IAM helps you create and manage users, groups, and roles to control access to AWS services and resources.
![1](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/2.IAM+Basics+and+Concepts/image2_1.png)

Here are the key components and capabilities of IAM:

Users : IAM enables you to create and manage individual users within your AWS account. Each user can possess unique security credentials, such as access keys or passwords, along with specific permissions to access AWS resources.

Groups : You can organize users into groups to manage their permissions collectively. Groups allow you to assign permissions to multiple users simultaneously, simplifying access management.

Roles : “IAM Roles” define a set of permissions that an entity (such as an AWS service, user, or application) can assume. They are helpful for granting temporary access to resources, facilitating secure cross-account access, or enabling applications to access AWS resources without needing access keys.

Policies : IAM policies are JSON documents that define permissions. These policies can be attached to users, groups, or roles to specify what actions are allowed or denied on specific AWS resources. Policies follow the least privilege (Security) principle, granting only the necessary permissions required to perform actions.

Authentication Process
1. Sign-in Credentials
Human users or applications use sign-in credentials such as usernames and passwords, access keys, temporary security tokens, or other authentication mechanisms to authenticate with AWS.

2. Match to a Principal
AWS authenticates these credentials against a principal entity trusted by the AWS account. This principal can be an IAM user, federated user, IAM role, or even an application with necessary permissions.

Authorization Process
1. Request for Access
Once authenticated, the principal makes a request to access specific AWS resources or services.

2. Authorization Check
The service or resource being accessed performs an authorization check to determine if the authenticated principal has the necessary permissions to perform the requested action.
This authorization check involves:
    Checking if the identity is on the list of authorized users for that resource.
    Evaluating policies associated with the authenticated identity (user, role, or federated user) to verify the level of access granted.
    Reviewing other relevant policies in effect that impact access control.


Access Decision
Based on the outcome of the authorization check:
    If the policies permit the requested action, access is granted to the resource or service.
    If the policies deny the action or if there's no explicit permission granted, access is denied.

Cross-Account Authorization
Authorization requests can originate not only within the same AWS account but also from other trusted AWS accounts (cross-account access).
Trusted accounts can define roles or permissions to allow access to specific resources, enabling secure sharing of resources between accounts.

This process ensures that authenticated entities are only granted access to the resources for which they have explicit authorization, based on the policies and permissions defined within IAM. It forms the core of secure access control within AWS environments.

IAM allows for granular control over access to AWS services and resources, emphasizing security best practices such as the principle of least privilege. This principle ensures that users and entities have only the permissions necessary for their tasks, minimizing potential security risks.

Overall, AWS IAM serves as a foundational service for managing access control and ensuring the security of your AWS infrastructure and resources. 

1. Apa Itu IAM?
    IAM (Identity and Access Management) adalah layanan AWS yang memungkinkan Anda mengelola akses ke berbagai layanan dan sumber daya AWS secara aman.
    IAM membantu Anda membuat dan mengelola users, groups, dan roles untuk mengontrol akses ke layanan dan sumber daya AWS.

2. Komponen dan Kemampuan Utama IAM
    a. Users
        IAM memungkinkan pembuatan dan pengelolaan pengguna individual di dalam akun AWS.
        Setiap pengguna dapat memiliki kredensial keamanan unik (access keys atau passwords) serta izin spesifik untuk mengakses sumber daya AWS.

    b. Groups
        Anda dapat mengatur pengguna ke dalam groups untuk mengelola izin mereka secara kolektif.
        Groups memungkinkan penugasan izin ke beberapa pengguna secara bersamaan, menyederhanakan manajemen akses.

    c. Roles
        IAM Roles mendefinisikan sekumpulan izin yang dapat diambil (assume) oleh suatu entitas (layanan AWS, pengguna, atau aplikasi).
        Berguna untuk memberikan akses sementara ke sumber daya, memfasilitasi akses lintas akun yang aman, atau memungkinkan aplikasi mengakses sumber daya AWS tanpa memerlukan access keys.

    d. Policies
        IAM policies adalah dokumen JSON yang mendefinisikan izin.
        Policies dapat dilampirkan ke users, groups, atau roles untuk menentukan tindakan apa yang diizinkan atau ditolak pada sumber daya AWS tertentu.
        Policies mengikuti prinsip least privilege (memberikan izin seminimal mungkin yang diperlukan untuk melakukan tindakan).

3. IAM Workflow (Proses Autentikasi dan Otorisasi)
    A. Authentication Process
    Sign-in Credentials → Pengguna manusia atau aplikasi menggunakan kredensial (username/password, access keys, temporary security tokens, atau mekanisme autentikasi lainnya) untuk mengautentikasi ke AWS.
    Match to a Principal → AWS mengautentikasi kredensial ini terhadap principal entity yang dipercaya oleh akun AWS (IAM user, federated user, IAM role, atau aplikasi dengan izin yang diperlukan).

    B. Authorization Process
    Request for Access → Setelah terautentikasi, principal membuat request untuk mengakses sumber daya atau layanan AWS tertentu.
    Authorization Check → Layanan atau sumber daya yang diakses melakukan pemeriksaan otorisasi untuk menentukan apakah principal yang terautentikasi memiliki izin yang diperlukan.

    Pemeriksaan otorisasi meliputi:
        Memeriksa apakah identitas tersebut berada dalam daftar pengguna yang diotorisasi untuk sumber daya itu.
        Mengevaluasi policies yang terkait dengan identitas yang terautentikasi (user, role, atau federated user) untuk memverifikasi tingkat akses yang diberikan.
        Meninjau kebijakan relevan lain yang berlaku yang mempengaruhi kontrol akses.

    C. Access Decision
    Jika policies mengizinkan tindakan yang diminta → akses diberikan (granted) ke resource atau layanan.
    Jika policies menolak tindakan atau tidak ada izin eksplisit yang diberikan → akses ditolak (denied).

    D. Cross-Account Authorization
    Permintaan otorisasi dapat berasal tidak hanya dari akun AWS yang sama tetapi juga dari akun AWS lain yang dipercaya (cross-account access).
    Akun yang dipercaya dapat mendefinisikan roles atau izin untuk mengizinkan akses ke sumber daya tertentu, memungkinkan berbagi sumber daya yang aman antar akun.

4. Prinsip Keamanan
    IAM memungkinkan granular control atas akses ke layanan dan sumber daya AWS.
    Menekankan praktik terbaik keamanan seperti prinsip least privilege (pengguna dan entitas hanya memiliki izin yang diperlukan untuk tugas mereka), meminimalkan potensi risiko keamanan.

5. Kesimpulan
    AWS IAM berfungsi sebagai layanan fundamental untuk mengelola kontrol akses dan memastikan keamanan infrastruktur dan sumber daya AWS.
