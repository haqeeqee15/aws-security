CloudWatch Logs Insights

Amazon CloudWatch Logs Insights is an AWS service that enables real-time analysis of log data from various sources. It offers interactive querying using a -like syntax, allowing users to filter, aggregate, and visualize data efficiently. The service provides automatic parsing, seamless integration with CloudWatch, and supports a variety of chart visualizations. CloudWatch Logs Insights is cost-effective as you pay for the queries you run and offers fine-grained access control. It simplifies log analysis, helping users identify patterns, troubleshoot issues, and monitor application performance effectively.


Basic Query Structure

In CloudWatch Logs Insights, you construct queries using a -like query language. The basic structure of a query involves the following components:

1. Selecting Fields:
fields @timestamp, @message, @fieldName
  Example:                 

fields @timestamp, @message, statusCode

Explanation: Specifies the fields you want to include in the query results. Common fields include `@timestamp` for the log event timestamp and `@message` for the log message. You can also include custom fields specific to your log events.

2. Filtering Data:
filter @fieldName = 'value'
filter @fieldName like 'pattern'
  Example:

filter @logStream = 'your-log-stream-name'
filter @message like 'error'  

Explanation: Filters log events based on specific criteria. You can filter events by exact match (‘=’) or use `like` with wildcards for pattern matching. Filters can be applied to built-in fields (@logGroup, @logStream, etc.) or custom fields in your log events.

3. Sorting Data:
sort @fieldName desc
  Example:

sort @timestamp desc

Explanation: Sorts the query results based on a specific field (@timestamp in this case) in ascending (`asc`) or descending (`desc`) order.

4. Limiting Results:
| limit number
  Example:      

| limit 50

  Explanation: Limits the number of results displayed to the specified number (`50` in this case). Useful for preventing large result sets.

Certainly! Advanced log queries in AWS CloudWatch Logs Insights involve utilizing more complex functions, operators, and techniques to gain deeper insights from your log data. Here's a guide to crafting advanced log queries.


Advanced Log Queries
1. Regular Expressions:

     Use `=~` operator to match log fields using regular expressions.

  Example:
filter @message =~ /error|exception/

Explanation: Filters log events where the `@message` field matches the regular expression pattern, containing either 'error' or 'exception'.

2. Nested Queries:
    Use subqueries to filter log data based on the results of another query.
  Example:

fields @timestamp, @message
| filter @message like 'error'
| sort @timestamp desc
| limit 10

Explanation: In this example, a subquery is used to filter log events containing 'error', and then the outer query sorts and limits the results from the subquery.

3. Mathematical and Comparative Operations:
    Utilize mathematical operators (+, -, *, /) and comparative operators (<, >, <=, >=, ==, !=) for advanced data analysis.
  Example:

fields @timestamp, @responseTime
| stats avg(responseTime) as avgResponseTime
| filter @responseTime > avgResponseTime * 2                  

Explanation: Calculates the average response time and filters log events where `@responseTime` is more than double the calculated average.

4. Data Aggregation and Grouping:
    Aggregate data using functions like `stats` and group log events based on specific fields.
  Example:

fields @timestamp, @logLevel
| stats count(*) by @logLevel
                  
Explanation: Counts log events grouped by the `@logLevel` field, providing insights into the distribution of log levels.

5. Time-Based Functions:
    Utilize time-based functions to analyze data over specific time intervals.
  Example:

fields @timestamp, @message
| filter @timestamp > now() - 1d

Explanation: Filters log events from the last 24 hours (`1d` represents 1 day) based on the ‘@timestamp’ field.

Examples
1. Security Incident Detection:
Scenario: Detecting Failed Login Attempts

Query:
fields @timestamp, @message
| filter @message like 'Failed login attempt'
| sort @timestamp desc
| limit 10

Explanation: This query filters log events where the message contains 'Failed login attempt'. It helps security teams quickly identify and investigate potential unauthorized access attempts.

2. Application Performance Monitoring:
Scenario: Identifying Slow API Requests

Query:
fields @timestamp, @requestDuration
| filter @requestType = 'API' and @requestDuration > 500
| sort @timestamp desc
| limit 20            

Explanation: This query filters log events related to API requests with a duration longer than 500 milliseconds. Monitoring such slow requests can help pinpoint performance bottlenecks in the application.

3. Error Analysis in Microservices Architecture:
Scenario: Analyzing Errors Across Microservices

Query:
fields @timestamp, @message
| filter @logStream like '/microservices/'
| filter @message like 'error'
| sort @timestamp desc
| limit 15            

Explanation: In a microservices architecture, logs might be distributed across various streams. This query filters errors from log streams related to microservices, aiding in troubleshooting issues across the architecture.

4. Resource Utilization Monitoring:
Scenario: Monitoring High CPU Utilization on EC2 Instances

Query:
fields @timestamp, @message
| filter @resourceType = 'EC2' and @metricType = 'CPUUtilization' and @metricValue > 80
| sort @timestamp desc
| limit 10            

Explanation: This query filters log events related to EC2 instances with CPU utilization exceeding 80%. Monitoring such instances can prevent performance degradation due to resource constraints.

5. Anomaly Detection with Machine Learning:
Scenario: Detecting Unusual Patterns in Access Logs

Query:
fields @timestamp, @ipAddress
| stats count(*) as requestCount by @ipAddress
| filter requestCount > 100
| sort requestCount desc
| limit 10

Explanation: This query aggregates log events by IP address and identifies IP addresses with more than 100 requests. Sudden spikes in request counts might indicate a potential DDoS attack or other abnormal activities.

6. Compliance Monitoring:
Scenario: Monitoring Access to Sensitive Data

Query:
fields @timestamp, @userName, @filePath
| filter @filePath like '/sensitive-data/'
| sort @timestamp desc
| limit 10

Explanation: This query filters log events related to access attempts to files containing sensitive data. Monitoring such access can help ensure compliance with data security policies.

1. Pengertian CloudWatch Logs Insights

    Layanan AWS untuk analisis data log secara real-time dari berbagai sumber.

    Menyediakan query interaktif dengan sintaks mirip SQL.

    Kemampuan: memfilter, mengagregasi, dan memvisualisasikan data secara efisien.

    Fitur: parsing otomatis, integrasi mulus dengan CloudWatch, dukungan berbagai visualisasi chart.

    Model biaya: pay per query (bayar per query yang dijalankan).

    Kontrol akses: granular (fine-grained).

    Tujuan utama: menyederhanakan analisis log, membantu identifikasi pola, troubleshooting, monitoring performa aplikasi.

2. Struktur Dasar Query

a. Selecting Fields (Memilih Field)

    Sintaks: fields @timestamp, @message, @fieldName

    Contoh: fields @timestamp, @message, statusCode

    Penjelasan: Menentukan field mana yang akan ditampilkan di hasil query.

        @timestamp → waktu log event.

        @message → isi pesan log.

        Bisa juga menambahkan field kustom.

b. Filtering Data (Menyaring Data)

    Sintaks:

        filter @fieldName = 'value' (pencocokan tepat)

        filter @fieldName like 'pattern' (pencocokan pola dengan wildcard)

    Contoh:

        filter @logStream = 'your-log-stream-name'

        filter @message like 'error'

    Penjelasan: Menyaring log event berdasarkan kriteria tertentu. Bisa diterapkan ke field bawaan (@logGroup, @logStream) atau field kustom.

c. Sorting Data (Mengurutkan Data)

    Sintaks: sort @fieldName desc (descending) atau asc (ascending)

    Contoh: sort @timestamp desc

    Penjelasan: Mengurutkan hasil query berdasarkan field tertentu.

d. Limiting Results (Membatasi Hasil)

    Sintaks: \| limit number

    Contoh: \| limit 50

    Penjelasan: Membatasi jumlah baris hasil yang ditampilkan. Berguna untuk mencegah hasil query yang terlalu besar.

3. Query Lanjutan (Advanced Log Queries)

a. Regular Expressions

    Operator: =~

    Contoh: filter @message =~ /error|exception/

    Penjelasan: Mencocokkan field log menggunakan pola regex. Contoh di atas mencari pesan yang mengandung 'error' atau 'exception'.

b. Nested Queries (Subquery)

    Contoh:
    text

    fields @timestamp, @message
    | filter @message like 'error'
    | sort @timestamp desc
    | limit 10

    Penjelasan: Subquery digunakan untuk memfilter data log berdasarkan hasil dari query lain.

c. Mathematical and Comparative Operations

    Operator matematika: +, -, *, /

    Operator perbandingan: <, >, <=, >=, ==, !=

    Contoh:
    text

    fields @timestamp, @responseTime
    | stats avg(responseTime) as avgResponseTime
    | filter @responseTime > avgResponseTime * 2

    Penjelasan: Menghitung rata-rata response time, lalu memfilter log yang response time-nya > 2x rata-rata.

d. Data Aggregation and Grouping

    Fungsi: stats untuk agregasi, by untuk pengelompokan.

    Contoh:
    text

    fields @timestamp, @logLevel
    | stats count(*) by @logLevel

    Penjelasan: Menghitung jumlah log event yang dikelompokkan berdasarkan @logLevel.

e. Time-Based Functions

    Fungsi waktu: now() dan operasi waktu (misal: 1d = 1 hari)

    Contoh:
    text

    fields @timestamp, @message
    | filter @timestamp > now() - 1d

    Penjelasan: Memfilter log event dari 24 jam terakhir.
