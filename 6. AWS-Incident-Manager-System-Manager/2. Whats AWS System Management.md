What is AWS System Manager?

AWS Systems Manager simplifies the management of operational data across multiple AWS services, automating tasks in both AWS and multicloud or hybrid environments. It allows you to group resources logically, enabling you to monitor API activity, configuration changes, notifications, alerts, software inventory, and patch compliance for each resource group. This centralized platform gives you complete visibility and control over your operations, facilitating efficient resource management and enhancing security in both AWS and multicloud or hybrid environments.

Improve your ability to see and manage operations across cloud, on-premises, and edge environments. Cut down on the time it takes to find and fix operational problems. Make sure that your instances meet patching, configuration, and custom policy requirements. Automate the setup and continuous management of your applications and resources.

AWS Systems Manager acts as the central operations center for your AWS applications and resources, consisting of four essential feature groups:

1. Operations Management
Explorer : This feature provides a visual representation of your AWS resources and their configurations, which helps you understand the relationships and dependencies between them.
OpsCenter : It serves as a central location for tracking and resolving operational issues. OpsCenter integrates with AWS CloudWatch and other AWS services, streamlining the incident response process.
Incident Manager : This feature facilitates a consistent and automated incident resolution process, enabling efficient coordination and communication during incidents.

2. Application Management
Application Manager : A service for creating, versioning, and deploying applications. It helps you define and deploy application configurations, ensuring consistency across your environment.
AppConfig : Allows you to create, manage, and quickly deploy application configurations. It helps you keep configurations separate from code, facilitating easier updates.
Parameter Store : A secure, hierarchical storage for configuration data management, including plaintext data and sensitive information like passwords.

3. Change Management
Automation : Enables you to create workflows to automate manual tasks, providing consistent and repeatable execution of operational tasks.
Change Manager : Helps you plan, track, and execute changes to your infrastructure. It provides a centralized view of changes and their approval status.
Maintenance Windows : Allows you to define a schedule for when operational tasks, such as patching, can be performed on your resources.

4. Node Management
Fleet Manager : Provides a simplified way to view and manage your instances at scale, allowing you to perform tasks such as system inventory, monitoring, and troubleshooting.
Session Manager : Offers secure and auditable instance management without the need for SSH/RDP access. You can manage instances through an interactive, browser-based shell.
Patch Manager : Automates the process of patching your instances with the latest security updates, making it easier to maintain a secure and compliant environment.


These features collectively contribute to effective management, monitoring, and automation of AWS resources across various aspects of your infrastructure.


Contribution to Security and Compliance

Security
By automating tasks like patch management and enforcing configurations, Systems Manager helps improve the security posture of your AWS environment. Timely patching and consistent configurations reduce the attack surface and mitigate potential security threats.

Compliance
Systems Manager contributes to compliance by providing a centralized view of your system configurations and patch compliance status. This visibility simplifies the process of demonstrating adherence to security and regulatory requirements.

Auditability
With features like Automation Runbooks and Session Manager, Systems Manager enhances auditability by providing detailed logs and records of changes made to instances. This is crucial for tracking system changes and meeting compliance standards.

How to Enable AWS Systems Manager?

Activating AWS Systems Manager requires various steps, and the procedure might differ based on your particular usage scenario and AWS setup. Here's a basic guide to activate AWS Systems Manager:

1. Access AWS Management Console
    Log in to the AWS Management Console

2. Navigate to Systems Manager
    In the AWS Management Console, go to the "Services" dropdown and select "Systems Manager" under the "Management & Governance" section.

Note : With your Amazon AWS account, you can access the section where these operations are performed at the URL below.

URL : https://us-east-1.console.aws.amazon.com/systems-manager/

https://letsdefend-images.s3.us-east-2.amazonaws.com/Courses/AWS+Incident+Manager+-+System+Manager/2.What+is+AWS+System+Manager/image2_3.png

Or use search bar

https://letsdefend-images.s3.us-east-2.amazonaws.com/Courses/AWS+Incident+Manager+-+System+Manager/2.What+is+AWS+System+Manager/image2_4.png

3. Check IAM Permissions
    Ensure that your IAM (Identity and Access Management) user or role has the necessary permissions to use AWS Systems Manager. At a minimum, the IAM entity should have the “AmazonSSMFullAccess” or the specific permissions required for the Systems Manager features you intend to use.

4. Verify AWS Region
    Confirm that you are working in the correct AWS region where you want to enable Systems Manager. The region selection is in the upper-right corner of the AWS Management Console.
https://letsdefend-images.s3.us-east-2.amazonaws.com/Courses/AWS+Incident+Manager+-+System+Manager/2.What+is+AWS+System+Manager/image2_5.png

5. Click Get Started and Enable Systems Manager
    Once in the Systems Manager console, you may see a welcome page or an option to "Get Started." Follow any prompts or navigate to the specific Systems Manager feature you want to use. (For this training Incident Manager only feature that we’ll use.)
https://letsdefend-images.s3.us-east-2.amazonaws.com/Courses/AWS+Incident+Manager+-+System+Manager/2.What+is+AWS+System+Manager/image2_6.png

6. Setup Systems Manager Agent (SSM Agent) on Instances
    If you plan to manage on-premises servers or EC2 instances, ensure that the Systems Manager Agent (SSM Agent) is installed and running on those instances. This agent facilitates communication between your instances and Systems Manager.

7. Configure Systems Manager Features
    Depending on your use case, configure the specific Systems Manager features you want to use, such as Automation, Patch Manager, or Run Command.

1. Definisi AWS Systems Manager
    Menyederhanakan manajemen data operasional di berbagai layanan AWS.
    Mengotomatiskan tugas di lingkungan AWS, multicloud, atau hybrid.
    Memungkinkan pengelompokan sumber daya secara logis (resource grouping).
    Memantau: aktivitas API, perubahan konfigurasi, notifikasi, alert, inventori software, dan kepatuhan patch untuk setiap grup sumber daya.
    Platform terpusat yang memberikan visibilitas dan kontrol penuh atas operasi.

Manfaat tambahan:
    Meningkatkan kemampuan melihat dan mengelola operasi di cloud, on-premises, dan edge environments.
    Mempercepat waktu untuk menemukan dan memperbaiki masalah operasional.
    Memastikan instance memenuhi persyaratan patching, konfigurasi, dan kebijakan kustom.
    Mengotomatiskan pengaturan dan manajemen aplikasi serta sumber daya secara berkelanjutan.

2. Empat Grup Fitur Esensial AWS Systems Manager
A. Operations Management
    Explorer: Representasi visual dari sumber daya AWS dan konfigurasi mereka; membantu memahami hubungan dan dependensi.
    OpsCenter: Lokasi terpusat untuk melacak dan menyelesaikan masalah operasional; terintegrasi dengan CloudWatch dan layanan AWS lainnya.
    Incident Manager: Memfasilitasi proses resolusi insiden yang konsisten dan otomatis; memungkinkan koordinasi dan komunikasi yang efisien selama insiden.

B. Application Management
    Application Manager: Membuat, membuat versi (versioning), dan menerapkan (deploy) aplikasi; mendefinisikan dan menerapkan konfigurasi aplikasi.
    AppConfig: Membuat, mengelola, dan menerapkan konfigurasi aplikasi dengan cepat; memisahkan konfigurasi dari kode.
    Parameter Store: Penyimpanan hierarkis yang aman untuk manajemen data konfigurasi (plaintext data dan informasi sensitif seperti password).

C. Change Management
    Automation: Membuat workflow untuk mengotomatiskan tugas manual; memberikan eksekusi tugas operasional yang konsisten dan dapat diulang (repeatable).
    Change Manager: Merencanakan, melacak, dan menjalankan perubahan infrastruktur; menyediakan tampilan terpusat dari perubahan dan status persetujuannya.
    Maintenance Windows: Mendefinisikan jadwal kapan tugas operasional (seperti patching) dapat dilakukan pada sumber daya.

D. Node Management
    Fleet Manager: Cara sederhana untuk melihat dan mengelola instance dalam skala besar; melakukan inventori sistem, monitoring, dan troubleshooting.
    Session Manager: Manajemen instance yang aman dan dapat diaudit tanpa perlu akses SSH/RDP; mengelola instance melalui shell interaktif berbasis browser.
    Patch Manager: Mengotomatiskan proses patching instance dengan update keamanan terbaru; memudahkan pemeliharaan lingkungan yang aman dan patuh.

3. Kontribusi terhadap Keamanan dan Kepatuhan
a. Security
    Mengotomatiskan tugas manajemen patch dan memberlakukan konfigurasi.
    Patching tepat waktu dan konfigurasi yang konsisten mengurangi attack surface dan memitigasi potensi ancaman keamanan.

b. Compliance
    Menyediakan tampilan terpusat dari konfigurasi sistem dan status kepatuhan patch.
    Visibilitas ini menyederhanakan proses pembuktian kepatuhan terhadap persyaratan keamanan dan regulasi.

c. Auditability
    Fitur seperti Automation Runbooks dan Session Manager meningkatkan auditability.
    Menyediakan log dan catatan detail tentang perubahan yang dilakukan pada instance.
    Sangat penting untuk melacak perubahan sistem dan memenuhi standar kepatuhan.

4. Cara Mengaktifkan AWS Systems Manager
Langkah 1 - Akses AWS Management Console
    Login ke AWS Management Console.

Langkah 2 - Navigasi ke Systems Manager
    Buka dropdown "Services" → pilih "Systems Manager" di bawah bagian "Management & Governance".
    URL: https://us-east-1.console.aws.amazon.com/systems-manager/

Langkah 3 - Periksa IAM Permissions
    Pastikan IAM user atau role memiliki izin yang diperlukan.
    Minimal: AmazonSSMFullAccess atau izin spesifik untuk fitur Systems Manager yang akan digunakan.

Langkah 4 - Verifikasi AWS Region
    Pastikan bekerja di region AWS yang benar (pemilihan region di pojok kanan atas AWS Management Console).

Langkah 5 - Klik Get Started dan Enable Systems Manager
    Ikuti prompt atau navigasi ke fitur Systems Manager spesifik yang akan digunakan (dalam pelatihan ini: Incident Manager).

Langkah 6 - Setup Systems Manager Agent (SSM Agent) pada Instances
    Jika akan mengelola server on-premises atau EC2 instances, pastikan SSM Agent terinstal dan berjalan.
    Agen ini memfasilitasi komunikasi antara instance dan Systems Manager.

Langkah 7 - Konfigurasi Fitur Systems Manager
    Sesuai dengan use case, konfigurasi fitur spesifik seperti Automation, Patch Manager, atau Run Command.
    Catatan: Selalu merujuk ke dokumentasi AWS untuk informasi terbaru dan paling detail.
