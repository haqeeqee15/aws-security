Policy Management

What is AWS IAM Policy?
An AWS IAM policy is a set of rules or permissions that define what actions are allowed or denied within an AWS environment. These policies are JSON documents that specify the resources, actions, effects (allow or deny), and optional conditions that determine access permissions for AWS users, groups, or roles.

IAM policies enable fine-grained control over access to AWS services and resources. They follow the principle of least privilege, allowing administrators to grant only the necessary permissions required for users, groups, or roles to perform their tasks or access specific resources.

IAM policies can be attached to IAM identities (users, groups, or roles) and also to AWS resources like S3 buckets, Lambda functions, or EC2 instances. They can be managed and customized to grant or restrict access to various AWS services and API actions based on specific requirements.

These policies can range from granting full administrative access to defining highly granular permissions for specific actions or resources. AWS provides predefined policies that cover common use cases, and administrators can also create custom policies tailored to their organization's needs.

Policy Structure Basics
JSON Format
IAM policies are written in JSON format, comprising key-value pairs within curly braces {}.

Components
Version : Indicates the policy language version (e.g., "Version": "2012-10-17").
Statement(s) : Contains an array of individual statements, each defining a specific permission or restriction.
Effect : Specifies whether the statement allows ("Allow") or denies ("Deny") access
Action : Describes the AWS service API actions (e.g., s3:GetObject, ec2:DescribeInstances) allowed or denied.
Resource : Specifies the AWS resources (e.g., ARNs, resource identifiers) the statement applies to.
Condition (Optional) : Allows for specifying additional conditions under which the policy is applicable (e.g., time, IP address).

Example IAM Policy in JSON
Here's a simple example illustrating the structure of an IAM policy in JSON:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::example-bucket/*"
    },
    {
      "Effect": "Deny",
      "Action": "s3:DeleteObject",
      "Resource": "arn:aws:s3:::example-bucket/confidential-file.txt",
      "Condition": {
        "IpAddress": {
          "aws:SourceIp": "192.168.1.1/32"
        }
      }
    }
  ]
}

                  
Version : Specifies the policy language version ("2012-10-17").
Statement 1 : Allows “s3:GetObject” action on all objects within the “example-bucket”.
Statement 2 : Denies “s3:DeleteObject” action for a specific file (confidential-file.txt) within the bucket, but only if the request doesn't originate from the specified IP address (192.168.1.1).

Policy Types
In AWS IAM, there are primarily three types of policies: “Identity-Based Policies”, “Resource-Based Policies”, and “ACLs (Access Control Lists)”. Each serves a distinct purpose in managing access within the AWS environment.

1. Identity-Based Policies
These policies are attached to IAM identities—users, groups, or roles—and define what actions are allowed or denied when those identities interact with AWS resources.
Examples : Managed policies (AWS-defined or custom), inline policies (directly attached to a single user, group, or role), and customer-managed policies.

2. Resource-Based Policies
These policies are attached directly to AWS resources (e.g., S3 buckets, Lambda functions), governing access to those resources.
Examples : S3 bucket policies, Lambda resource policies, and SNS topic policies.

3. ACLs (Access Control Lists)
ACLs are legacy mechanisms for controlling access to S3 buckets and objects. They provide a simple way to manage access by defining which AWS accounts can access the resources.
Examples : S3 bucket and object ACLs which specify access permissions for individual AWS accounts.

Differences and Usage
Identity-Based Policies : Used to control access for IAM users, groups, or roles within an account. They define what actions these entities can perform on AWS resources.
Resource-Based Policies : Applied directly to AWS resources, allowing external entities to access those resources. For instance, an S3 bucket policy can grant access to users from different accounts or public access.

ACLs : Less commonly used than resource-based policies. They manage access control for S3 buckets and objects but are less flexible compared to resource policies.

Creating Policies
Let’s create a custom policy granting permissions for managing EC2 instances.

Steps to Create Custom Policies and Attach Them:
1. IAM Console
    Access the IAM Management Console: https://console.aws.amazon.com/iam/
    Select "Policies" from the left-hand menu.
    Click "Create policy."
![1](https://ld-images-2.s3.us-east-2.amazonaws.com/AWS+Identity+and+Access+Management/6.Policy+Management/image6_1.png)

2. Write Custom Policy
Here is the policy that we can create:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:StartInstances",
        "ec2:StopInstances",
        "ec2:RebootInstances",
        "ec2:TerminateInstances"
      ],
      "Resource": "*"
    }
  ]
}

Version : Specifies the policy language version.
Statement : Contains an "Allow" statement with various EC2 actions.
    Actions : Permits actions such as “DescribeInstances”, “StartInstances”, “StopInstances”, “RebootInstances”, and “TerminateInstances” for EC2 instances.
    Resource : The wildcard (*) signifies permission to perform these actions on all EC2 instances.

This policy grants the capability to describe instances and perform lifecycle operations (start, stop, reboot, terminate) on EC2 instances across the entire AWS account. Adjust the actions and resource constraints according to your specific requirements for managing EC2 instances within your AWS environment.

AWS Managed Policies
AWS Managed Policies are predefined sets of permissions created and managed by AWS. These policies are designed to provide commonly needed access permissions for various AWS services and resources, ensuring security best practices and adherence to the principle of least privilege.

Key aspects of AWS-managed policies include:
1. Managed by AWS: Created, updated, and managed by AWS itself, these policies ensure alignment with AWS service updates, best practices, and security standards.
2. Ready-to-Use: Readily available within the AWS Management Console, these policies cover a wide range of permissions needed for typical scenarios.
3. Least Privilege Principle: Follow the principle of least privilege, granting only the necessary permissions required for common use cases without providing unnecessary access.
4. Granular Permissions: Offer fine-grained control over access to AWS services and resources by defining actions and resources that can be accessed.

Types of Managed Policies
AWS Managed Policies : Policies curated and maintained by AWS.
Customer Managed Policies : Custom policies created by AWS users to meet specific organizational needs.
Inline Policies : Policies attached directly to a single IAM user, group, or role.

Examples of AWS Managed Policies
AmazonS3ReadOnlyAccess : Provides read-only access to Amazon S3 buckets and objects.
AmazonEC2FullAccess : Grants full access to Amazon EC2 resources.
AmazonDynamoDBReadOnlyAccess : Allows read-only access to Amazon DynamoDB tables.

These policies offer a convenient way to manage access control within AWS, allowing administrators to assign permissions efficiently without creating policies from scratch. By using AWS Managed Policies, users can adhere to established security best practices and easily apply permissions to IAM entities within their AWS environment. 

1. Apa Itu AWS IAM Policy?
    IAM policy adalah sekUmpulan aturan atau izin yang mendefinisikan tindakan apa yang diizinkan (allowed) atau ditolak (denied) di dalam lingkungan AWS.
    Policies adalah dokumen JSON yang menentukan sumber daya, tindakan, efek (allow atau deny), dan kondisi opsional yang menentukan izin akses untuk pengguna, group, atau role AWS.
    IAM policies memungkinkan fine-grained control (kontrol terperinci) atas akses ke layanan dan sumber daya AWS.
    Policies mengikuti prinsip least privilege (memberikan izin minimal yang diperlukan).
    Policies dapat dilampirkan ke IAM identities (users, groups, roles) dan juga ke AWS resources (S3 buckets, Lambda functions, EC2 instances).
    Policies dapat dikelola dan disesuaikan untuk memberikan atau membatasi akses ke berbagai layanan AWS dan tindakan API berdasarkan kebutuhan spesifik.

Komponen-komponen dalam policy:
    Version → Menunjukkan versi bahasa policy (contoh: "Version": "2012-10-17")
    Statement(s) → Berisi array dari pernyataan individual, masing-masing mendefinisikan izin atau pembatasan spesifik
    Effect → Menentukan apakah pernyataan mengizinkan ("Allow") atau menolak ("Deny") akses
    Action → Menjelaskan tindakan API layanan AWS yang diizinkan atau ditolak (contoh: s3:GetObject, ec2:DescribeInstances)
    Resource → Menentukan sumber daya AWS (ARNs, resource identifiers) yang menjadi subjek pernyataan
    Condition (Opsional) → Memungkinkan penentuan kondisi tambahan di mana policy berlaku (contoh: waktu, alamat IP)

Contoh IAM Policy dalam JSON:
    Versi: "2012-10-17"
    Statement pertama: Effect "Allow", Action "s3:GetObject", Resource "arn:aws:s3:::example-bucket/*"
    Statement kedua: Effect "Deny", Action "s3:DeleteObject", Resource "arn:aws:s3:::example-bucket/confidential-file.txt", dengan kondisi IpAddress "aws:SourceIp": "192.168.1.1/32"

3. Policy Types
a. Identity-Based Policies
    Dilampirkan ke IAM identities (users, groups, atau roles).
    Mendefinisikan tindakan apa yang diizinkan atau ditolak ketika identitas tersebut berinteraksi dengan sumber daya AWS.
    Contoh: Managed policies (AWS-defined atau custom), inline policies, customer-managed policies.

b. Resource-Based Policies
    Dilampirkan langsung ke AWS resources (S3 buckets, Lambda functions, SNS topics).
    Mengatur akses ke sumber daya tersebut.
    Contoh: S3 bucket policies, Lambda resource policies, SNS topic policies.

c. ACLs (Access Control Lists)
    Mekanisme lama (legacy) untuk mengontrol akses ke S3 buckets dan objek.
    Menyediakan cara sederhana untuk mengelola akses dengan mendefinisikan akun AWS mana yang dapat mengakses sumber daya.
    Contoh: S3 bucket and object ACLs.

4. Perbedaan dan Penggunaan
    Identity-Based Policies → Digunakan untuk mengontrol akses bagi IAM users, groups, atau roles di dalam suatu akun. Mendefinisikan tindakan apa yang dapat dilakukan entitas tersebut pada sumber daya AWS.
    Resource-Based Policies → Diterapkan langsung ke sumber daya AWS, memungkinkan entitas eksternal (akun berbeda atau publik) untuk mengakses sumber daya tersebut.
    ACLs → Jarang digunakan dibandingkan resource-based policies. Hanya untuk S3 buckets dan objek, kurang fleksibel.

5. Creating Policies (Membuat Custom Policy)

    Pilih "Policies" dari menu sebelah kiri.
    Klik "Create policy".
    Pilih tab "JSON" dan tempelkan custom policy JSON.
    Klik "Next".
    Beri nama policy.
    Klik "Create policy".

Contoh custom policy untuk mengelola EC2 instances:
    Version: "2012-10-17"
    Effect: "Allow"
    Actions: ec2:DescribeInstances, ec2:StartInstances, ec2:StopInstances, ec2:RebootInstances, ec2:TerminateInstances

Policy ini memberikan kemampuan untuk mendeskripsikan instance dan melakukan operasi lifecycle (start, stop, reboot, terminate) pada semua EC2 instances di seluruh akun AWS.

6. AWS Managed Policies
Definisi:
    AWS Managed Policies adalah kumpulan izin yang telah ditentukan sebelumnya, dibuat dan dikelola oleh AWS.
    Dirancang untuk memberikan izin akses yang umum dibutuhkan untuk berbagai layanan dan sumber daya AWS.
    Memastikan praktik terbaik keamanan dan kepatuhan terhadap prinsip least privilege.

Karakteristik:
    Managed by AWS → AWS membuat, memperbarui, dan mengelola policies ini.
    Ready-to-Use → Tersedia langsung di AWS Management Console.
    Least Privilege Principle → Memberikan izin minimal yang diperlukan untuk use case umum.
    Granular Permissions → Kontrol terperinci atas akses ke layanan dan sumber daya AWS.

Jenis Managed Policies:
    AWS Managed Policies → Policies yang dikurasi dan dipelihara oleh AWS.
    Customer Managed Policies → Policies kustom yang dibuat oleh pengguna AWS untuk memenuhi kebutuhan organisasi spesifik.
    Inline Policies → Policies yang dilampirkan langsung ke satu IAM user, group, atau role.

Contoh AWS Managed Policies:
    AmazonS3ReadOnlyAccess → Akses baca-only ke S3 buckets dan objek.
    AmazonEC2FullAccess → Akses penuh ke sumber daya EC2.
    AmazonDynamoDBReadOnlyAccess → Akses baca-only ke tabel DynamoDB.

Kesimpulan:
AWS Managed Policies menawarkan cara yang nyaman untuk mengelola kontrol akses di AWS, memungkinkan administrator menetapkan izin secara efisien tanpa membuat policies dari awal. Dengan menggunakan AWS Managed Policies, pengguna dapat mematuhi praktik terbaik keamanan yang telah ditetapkan dan dengan mudah menerapkan izin ke IAM entities di lingkungan AWS mereka.
